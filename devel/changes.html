    Change Logs¶

    Version 9¶

    Release 9.0 (Unreleased)¶

    Highlights¶

    • SPA and StepM now studentize the loss differentials when studentize=True, which is the default. The option had no effect in previous versions, and so p-values, critical values and the superior models obtained using the default arguments differ from previous versions. Use studentize=False for the previous statistics.

    • Added FIAPARCH, a fractionally integrated asymmetric power ARCH volatility process (contributed by gjunjie).

    • Added MAMean, a moving average mean model that can be used with any volatility process and distribution (contributed by premdev1234).

    • Added append(), which adds observations to a mean model in-place so that parameters estimated using earlier data can be used to produce forecasts without re-estimating the model.

    • Added PreWhitenedRecolored, which implements the VAR-HAC and pre-whitened recolored long-run covariance estimators (contributed by WatchTree-19).

    • Added NGARCH, the nonlinear asymmetric GARCH of Engle and Ng, the VaR backtests of Kupiec and Christoffersen and the Basel traffic light, and LocalBlockBootstrap, the local block bootstrap of Paparoditis and Politis.

    • The automatic bandwidth of the kernel covariance estimators can use the AR(1) plug-in method of Andrews (1991) with bandwidth_method="andrews", and the default method of Newey and West (1994) now gives the bandwidths and estimates of the R package sandwich, which changes every automatic bandwidth. See “Changes that alter results”.

    • Added the residual diagnostics excess_kurtosis(), hill_estimator() and var_ratio() (contributed by albystack), and Ng and Perron’s modified AIC, method="maic", for selecting the number of lags in the ADF, DFGLS and ZivotAndrews tests.

    • Fixed bugs that change results. The most important are the studentization of SPA and StepM, the simulation and analytic forecasts of RiskMetrics2006, the analytic forecasts of GJR-type models with skewed distributions, BCa confidence intervals of functions that return several statistics, ARCHInMean models, DFGLS and auto_bandwidth() with integer data, and the ADF-Z critical values and p-values without a trend, which PhillipsPerron uses with test_type="rho". See “Changes that alter results”.

    • The arguments of the public API are validated consistently. An invalid argument raises a TypeError (wrong type) or a ValueError (value that is not allowed) with a message that names the argument, shows the value and says what is accepted, the string options are not case sensitive, and integer, Boolean and list data are converted to float64. Some calls that were accepted by earlier versions now raise. See “Backward-incompatible changes”.

    • Python 3.10 to 3.15 are supported, with wheels for each of them. 9.0 is the last release that supports Python 3.10 and NumPy 1.x.

    New features¶

    • Added FIAPARCH, a fractionally integrated asymmetric power ARCH volatility process that extends FIGARCH with an asymmetry parameter and a power parameter, delta, which is estimated unless a value is provided. The orders p, o and q can be 0 or 1. It can be used in arch_model() with vol="FIAPARCH". Analytic forecasts are only available for a horizon of 1, and longer horizons require method="simulation" or method="bootstrap". The backcast of fit is a variance, as for the other volatility processes, and the model with an estimated delta and the one with the same delta fixed have the same log-likelihood. Contributed by gjunjie (GH833, GH926).

    • Added NGARCH, the nonlinear asymmetric GARCH volatility process of Engle and Ng (1993), which is called NAGARCH in the R package rugarch. o is the number of innovations that have a shift. It can be used in arch_model() with vol="ngarch", which requires o to be at least 1, since a model without a shift is a GARCH. Analytic forecasts are exact at all horizons, and simulation and bootstrap forecasts are available. fit issues a ValueWarning when the estimated persistence is 1 or more, which the estimation constraints do not exclude (GH636, GH966).

    • Added MAMean, a moving average mean model of order q with an optional constant that can be used with any volatility process and distribution. Analytic, simulation and bootstrap forecasts include the moving average terms for the first q steps. It is a class only: arch_model does not support mean="MA". Contributed by premdev1234 (GH147, GH778, GH903).

    • Added append() to the mean models, which adds new observations to a model in-place. Parameters estimated using earlier data can then be used to produce forecasts, or results using fix(), without re-estimating the model. The new data must have the same type as the data used to construct the model, and models that include exogenous regressors require x for the new observations (GH674).

    • Added PreWhitenedRecolored, which implements the VAR-HAC (den Haan and Levin) and pre-whitened recolored (Andrews and Monahan) long-run covariance estimators, and the ZeroLag kernel that it uses for VAR-HAC, which is selected with kernel=None. The order, residuals and residual covariance of the VAR are available as order, resid and resid_cov. Contributed by WatchTree-19 (GH874, GH894).

    • Added bandwidth_method to the kernel covariance estimators in arch.covariance.kernel, to PreWhitenedRecolored, to the fit methods of DynamicOLS, FullyModifiedOLS and CanonicalCointegratingReg, and to phillips_ouliaris(). The default, "newey-west", is the nonparametric method of Newey and West (1994). "andrews" is the AR(1) plug-in method of Andrews (1991), whose bandwidths equal those of bwAndrews in the R package sandwich (GH887, GH964, GH985).

    • Added the residual diagnostics excess_kurtosis(), hill_estimator() and var_ratio(), which use standardized residuals. The results of a model also have excess_kurtosis, hill_estimator() and var_ratio(), which use the standardized residuals and the estimated distribution of the model. Contributed by albystack (GH845, GH850).

    • Added the VaR backtests var_exceptions(), which finds the observations where the loss exceeds the VaR, kupiec_pof(), the proportion of failures test of Kupiec (1995), christoffersen_independence() and christoffersen_conditional_coverage(), the independence and conditional coverage tests of Christoffersen (1998), and traffic_light(), the zone of the Basel traffic light, which is returned as a TrafficLightResult. p is always the probability of an exception, such as 0.01 for a 99% VaR, and must be in (0, 0.5]. The unconditional and conditional coverage statistics equal those of VaRTest in the R package rugarch (GH904, GH965).

    • Added LocalBlockBootstrap, the local block bootstrap of Paparoditis and Politis (2002), for series whose properties change slowly over time. Each block of the data is replaced by a block that starts at most locality observations from it, so that a bootstrap sample only mixes nearby blocks (GH617, GH967).

    • Added method="maic" to the automatic lag selection of ADF, DFGLS and ZivotAndrews. It selects the lag that minimizes the modified AIC of Ng and Perron (2001). Contributed by ZacKienzle2 (GH889).

    • Added the keyword argument low_memory to engle_granger(), which is passed to the ADF test of the residuals. The default, None, selects the lag selection algorithm automatically. Contributed by ZacKienzle2 (GH876).

    • Kernel names are now looked up in one place, arch.covariance.kernel.get_kernel_estimator, using the list arch.covariance.kernel.KERNELS. All estimators that take a kernel accept the same names, in any case and with hyphens or underscores ignored, and raise the same error, which lists the available kernels, for an unknown name. As a result, the fit methods of FullyModifiedOLS and CanonicalCointegratingReg accept names such as "quadratic-spectral", which raised KeyError in previous versions. Contributed by WatchTree-19 (GH873).

    • The string options of the public API are not case sensitive, and the lower case spelling is stored. For example forecast(method="Analytic", align="Target"), plot(annualize="d"), ADF(y, trend="C", method="AIC"), engle_granger(y, x, trend="CT"), add_trend(x, trend="CT") and IIDBootstrap.conf_int(func, method="BCa", tail="Upper") now work, where they raised an error in previous versions. The method of MCS, the cov_type of fit and the form of ARCHInMean are stored in lower case. An option that is not accepted raises a ValueError that lists the accepted values (a TypeError for a value that is not a string). See “Bug fixes” for the options that were silently accepted (GH947).

    • Lists and other array_like objects are accepted as the data of the covariance estimators, PreWhitenedRecolored, cov_nw, SPA, StepM, MCS and the methods of the volatility processes, as the models and the unit root tests already did. Data that cannot be converted to float64, such as strings, raise a TypeError that names the argument (GH948).

    • Added the keyword argument asym_weight to the forecast method of the volatility processes. It is the value of \(E[z^2 1(z<0)]\) of the distribution that the analytic forecasts of processes with an asymmetric term use, and the default is 0.5 (GH933, GH939).

    • Integer positions can be negative, and then count from the end as in Python indexing. This applies to first_obs and last_obs of fit and fix, to start of forecast and hedgehog_plot, to start of the forecast method of the volatility processes, and to the integer arguments of cutoff_to_index and find_index in arch.utility.array. first_obs and last_obs are slice bounds, so last_obs=-1 drops the last observation and first_obs=-100 starts 100 observations from the end. start is the index of an observation, so start=-1 is the last observation. A position outside [-nobs, nobs] raises a ValueError, and dates are unchanged (GH956).

    • "horizon" is an official alias of "target" for the align argument of forecast and of ARCHModelForecast. It is documented, listed in the error for an invalid align, and now accepted by the forecast method of the models, which rejected it, as well as by the results (GH956).

    Changes that alter results¶

    These changes fix bugs that returned incorrect results, or make an option that had no effect work as documented. Each entry says who is affected and, where there is one, how to restore the previous results.

    • Fixed SPA and StepM so that studentize=True (the default) studentizes the loss differentials. In previous versions the option had no effect on the results. The loss differentials are now studentized in the original data and inside each bootstrap replication, using the standard error from a kernel long-run variance estimator that matches the bootstrap, or from a nested bootstrap if nested=True. Everyone who uses the default arguments is affected: the p-values, the critical values and the superior models can change. Use studentize=False for the statistics that were always used in previous versions. Studentizing in each replication makes the default about 3 times slower (measured with 2000 observations, 100 models and 1000 replications). Started by WatchTree-19 (GH871) and completed in GH882.

    • The critical values of SPA and StepM apply to the studentized mean loss differentials, so code that compares critical_values with mean loss differentials or that uses fixed thresholds must change. In one battery of simulated losses the 5% consistent critical value changed from 0.1375 to 2.581 (stationary bootstrap), from 0.1453 to 2.595 (circular) and from 0.1449 to 2.425 (moving block). With weak evidence (300 observations, 15 models, 300 replications) the lower, consistent and upper p-values of the stationary bootstrap changed from 0.0067, 0.0200 and 0.0200 to 0.0033, 0.0067 and 0.0133, and those of the moving block bootstrap from 0.0133, 0.0300 and 0.0367 to 0.0100, 0.0133 and 0.0167, so they can move in either direction. With a strongly superior model the p-values are 0 before and after, and only the critical values change (GH871, GH882).

    • nested=True in SPA and StepM now computes the variances used to studentize in every bootstrap replication using a nested bootstrap, and not only in the original data, and never uses the kernel estimator. The run time grows with the square of reps: with 500 observations, 10 models and 200 replications it increased from 0.04 seconds to about 3 seconds. nested=True requires studentize=True and raises a ValueError otherwise, so there is no way to restore the previous statistics with nested=True (GH882).

    • When nested=False, the long-run variances in SPA and StepM, which are used to select the models that are re-centered when computing the consistent p-value, now use the kernel that matches the bootstrap. Previously they always used the stationary bootstrap kernel, so the consistent p-value can also change with studentize=False when using the circular or moving block bootstraps. Results of the stationary bootstrap do not change. In the examples that were checked the effect on the critical values was small: the 5% consistent critical value of the circular bootstrap changed from 0.1453 to 0.1391 (-4%), and the 10% value of the moving block bootstrap from 0.1235 to 0.1138 (-8%) (GH882).

    • Fixed the simulation and bootstrap forecasts of RiskMetrics2006. The simulated paths started from the variance at the forecast origin instead of the one-step-ahead variance, and so the forecast of the first step differed from the analytic forecast and the error carried into longer horizons. For a zero mean model of the last 1,500 daily S&P 500 returns, the simulated variance of the first step at the last origin changes from 3.048 to 2.774 (-9%), which is the analytic forecast, and the means of the simulated variances of the later steps are lower by a similar amount. For a constant mean model of NASDAQ returns with Student’s t errors the variance changes from 3.383 to 5.462 (+61%) at one origin when the volatility had just increased. Analytic forecasts, estimation and fix are not changed by this fix. Contributed by WatchTree-19 (GH868).

    • Fixed the multi-step analytic variance forecasts of RiskMetrics2006, which repeated the one-step forecast at every horizon. They are now the expected variance path implied by the process, which is linear in its EWMA components. Forecasts of the first step do not change, and the simulation forecasts are consistent with the analytic ones. For the model above the analytic forecast at the last origin, 2.774 at every horizon, becomes 2.774, 2.705, 2.642 and 2.536 for horizons 1 to 3 and 5 and 2.343 for horizon 10 (-16%). The change can have either sign, depending on whether the volatility is above or below its long-run level at the origin. There is no option to restore the old forecasts. Contributed by raashish1601 (GH885, GH934).

    • Fixed the multi-step analytic variance forecasts of GARCH models with an asymmetric term (o > 0, such as GJR-GARCH), MAMean models and MIDASHyperbolic with asym=True. In previous versions the forecast assumed that half of the variance of the standardized residual comes from negative shocks, \(E[z^2 1(z<0)] = 0.5\), which only holds for symmetric distributions. The forecasts now use the value of the distribution, for example of SkewStudent. Forecasts with a symmetric distribution are unchanged, and so are simulation and bootstrap forecasts. With a skewed distribution the forecasts for horizons beyond 1 change and the change accumulates with the horizon: for a GJR-GARCH(1,1,1) model of the last 1,500 daily S&P 500 returns with a skew t distribution that has \(\eta=7.6\) and \(\lambda=-0.16\) the variance forecasts for horizons 10 and 20 at the last origin change from 2.085 and 1.740 to 2.450 and 2.383. The stationarity constraint of the volatility process and the initial value used by simulate still use the value 0.5 (see GH867). Contributed by shaneraphel (GH870, GH933).

    • Fixed the acceleration constant of BCa confidence intervals computed by conf_int() when the function returns more than one statistic. The jackknife estimates of each statistic were centered at the mean of the estimates of all of the statistics, and not at their own mean, which changed the intervals when the statistics are at different levels. Intervals of a function that returns one statistic are not changed. For example, the 90% interval of the mean, when an IID bootstrap computes the mean, standard deviation and skewness, changed from [-0.1623, 0.0261] to [-0.1625, 0.0253], which is the interval of the mean alone, and the lower endpoint for the skewness from -0.0060 to -0.0050. Typical changes of the endpoints are 0.2% to 3%, and the largest relative change was 17%, for an endpoint near 0. Reported by lucaluo925 and contributed by WatchTree-19 (GH866, GH869).

    • Fixed the residuals and conditional volatility of ARCHInMean results. In previous versions resid, conditional_volatility, std_resid and rsquared, and the quantities derived from them such as the output of summary and arch_lm_test, were computed as if the in-mean parameter kappa was 0, so they did not match the log-likelihood. They now use the same recursion as the log-likelihood, for all values of form and for both fit and fix. The estimated parameters, log-likelihood and standard errors are unchanged. The values change whenever kappa is not 0. For example, for a GARCH(1,1) model with one AR lag fit to the daily S&P 500 returns in arch.data.sp500, the conditional volatility changes by at most 3.7% (form="log"), 5.1% ("vol") and 6.1% ("var"), the largest change in a residual is 0.15, 0.53 and 1.1, and R-squared changes from 0.0021 to 0.0021, from 0.0039 to 0.0012 and from 0.0047 to -0.0006. R-squared can now be negative for these models (GH909).

    • Fixed ARCHInMean models that use a GARCH or FIGARCH volatility process with power != 2 (for example TARCH and AVGARCH). The volatility updaters used in estimation returned the recursion value \(\sigma^{power}\) instead of the variance \(\sigma^2\), so the in-mean term and the log-likelihood used the wrong conditional variance. The log-likelihood, estimates, standard errors and summary change for these models; models with power=2 are unchanged. For example, for a GARCH(1,1,1) model with power=1 and one AR lag fit to the second half of the daily S&P 500 returns in arch.data.sp500, the log-likelihood changes from -3154.8 to -3111.1 and the in-mean coefficient kappa from 0.217 to 0.059 (form="var"). For a GARCH(1,0,1) model with power=1.5 the log-likelihood changes from -3206.3 to -3190.5, and for a FIGARCH(1,d,1) model with power=1 from -3284.6 to -3189.9 (GH927).

    • Fixed simulation and bootstrap variance forecasts of APARCH models with p >= 2 and o >= 1. In previous versions the asymmetric term |e| - gamma * e overwrote the stored absolute shock, so from the second forecast horizon on the lagged shocks were wrong. Analytic, one-step and p = 1 forecasts are unchanged. The size of the change depends on the parameters, the data and the horizon: the simulated variance forecast of an APARCH(2,1,1) model changed by between 7% and 34% in the cases that were checked (12% at horizon=2 in a typical case, from 0.271 to 0.239) and by about 1% for a model of S&P 500 returns with moderate parameters (GH911).

    • Fixed simulation forecasts of GARCH models with power != 2 (for example TARCH and AVGARCH models) that start in the first max(p, o, q) observations. In previous versions the pre-sample values were raised to the power power / 2 a second time, so the forecast made at start=0 was wrong for any model with more than one lag. Forecasts that start later in the sample, and the analytic and bootstrap forecasts, are unchanged. For example, the one-step simulated variance of a GARCH(2,0,0) model with power=1 at the first observation changes from 0.4184 to 0.4059 (3.1%), and that of a GARCH(2,1,2) model with power=1 changes by 3.6% (GH913).

    • Fixed conf_int with sampling="semi-parametric" or sampling="parametric" in the bootstrap classes in arch.bootstrap. In previous versions the params (and state) keywords used to simulate the data were added to the data of the bootstrap, so method="studentized" raised an error when the studentization used a nested bootstrap. When extra_kwargs was also given, the nested bootstrap silently used the non-parametric statistic. The nested bootstrap now simulates the data in the same way as the outer bootstrap, so studentized intervals from the nested bootstrap with these samplers change from previous versions (GH916).

    • Fixed CanonicalCointegratingReg so that df_adjust=True scales the entire estimate of the conditional long-run variance, as FullyModifiedOLS does. Previously only the first term was scaled, which overstated the parameter covariance and long_run_variance when the regressors are endogenous. Results using the default, df_adjust=False, are not changed. In regressions with 390 to 400 observations and 2 or 3 regressors the covariance and long-run variance fall by 0.016% to 0.15%, the standard errors and t-values by 0.008% to 0.07%, and the p-values by up to 1.3%. In a small sample (100 observations, an endogenous regressor and a bandwidth of 4) the standard errors with df_adjust=True were 1.9% larger than with df_adjust=False and are now 1.0% larger, and the long-run variance was 3.8% larger and is now 2.1% larger. Contributed by WatchTree-19 (GH872).

    • Fixed DFGLS when the data are integers. The quasi-differenced data were truncated to integers, which produced a statistic and p-value that differ from those of the same data stored as floats. Results for data that are floats are not changed. For example, the statistic of one integer series changed from -0.3005 to -0.3378, and its p-value from 0.581 to 0.567 (and, with lags=2, the statistic from -0.2618 to -0.2970). Convert the data to floats to obtain the previous statistic. Contributed by raashish1601 (GH883).

    • Fixed auto_bandwidth() so that the autocovariances are not truncated to integers. In previous versions any series with non-integer values could return an incorrect bandwidth or raise ZeroDivisionError, which happened when all of the autocovariances were less than 1 in absolute value. For example, the bandwidths for the Bartlett, Parzen and quadratic spectral kernels of daily S&P 500 percent returns change from 9.655, 19.65 and 7.223 to 9.816, 19.94 and 7.256 (+1.7%, +1.5% and +0.5%), and the Bartlett and quadratic spectral bandwidths of the first difference of the AAA bond yield change from 9.17 and 1.956 to 9.76 and 3.142 (+6.4% and +61%). Only auto_bandwidth() is affected: the kernel classes, PhillipsPerron and KPSS do not use it. Contributed by ZacKienzle2 (GH886).

    • Fixed the automatic bandwidth of the kernel covariance estimators in arch.covariance.kernel, so that the bandwidths and the estimates equal those of the R package sandwich. Every estimate with an automatic bandwidth changes, including those of PreWhitenedRecolored, DynamicOLS, FullyModifiedOLS, CanonicalCointegratingReg and phillips_ouliaris() when bandwidth is not given. There are three changes:

      • The number of autocovariances in the pilot estimate of the optimal bandwidth, opt_bandwidth, is the integer part of \(4(T/100)^{r}\), as in Newey and West (1994) and auto_bandwidth(). Previously it was rounded up, so that one more autocovariance was used whenever \(4(T/100)^{r}\) is not an integer. opt_bandwidth now equals bwNeweyWest of sandwich.

      • The kernels that are 0 beyond a finite lag, which are all except the quadratic spectral kernel, weight lag \(h\) by \(k(h/(H+1))\) for a bandwidth \(H\), while the optimal bandwidth \(S\) of Andrews (1991) and Newey and West (1994) is that of \(k(h/S)\). \(S\) was used as \(H\), which gave the weights of \(S+1\). The estimated bandwidth of these kernels is now \(\max(S-1, 0)\), so that the weights are those of \(S\), as in kernHAC of sandwich (and NeweyWest for the Bartlett kernel with force_int=True). opt_bandwidth is still \(S\), and so Bartlett(x, bandwidth=est.opt_bandwidth) is not the same as Bartlett(x).

      • A bandwidth that is not an integer, estimated or given, uses every lag with a positive weight. The lag \(\lfloor H \rfloor + 1\) was not used. An integer bandwidth gives the same estimates as before.

      For example, the Bartlett, Parzen and quadratic spectral bandwidths of the daily S&P 500 percent returns in arch.data.sp500 change from 22.88, 31.99 and 13.25 to 30.96, 34.50 and 13.61, and their opt_bandwidth to 31.96, 35.50 and 13.61. The constant of the Tukey-Parzen kernel is also corrected from 1.8576 to 1.8587, which changes its automatic bandwidth slightly. Pass bandwidth to use a specific value (GH964, GH983).

    • Fixed the critical values and p-values of the ADF-Z statistic without a trend (regression="n"), which PhillipsPerron uses with test_type="rho" and trend="n", and which mackinnoncrit and mackinnonp return with dist_type="adf-z". The values are from a new simulation that starts the random walk at 0. The 1%, 5% and 10% critical values with 100 observations change from -10.78, -6.13 and -4.27 to -13.08, -7.78 and -5.56, and the asymptotic ones from -13.30, -7.83 and -5.57 to -13.69, -8.04 and -5.71. In small samples the previous critical values were wrong: with 10 observations they were 20.32, 13.84 and 10.54, and are now -8.95, -5.98 and -4.41. For example the p-value of a statistic of -8 changes from 0.0477 to 0.0504. The tables with a constant or a trend are also from the new simulation. Their critical values change by less than 0.005 with 25 or more observations and their p-values below 0.15 by at most 0.0001. Contributed by mkzung (GH971, GH972, GH973, GH980).

    • The p-value of the ADF-Z statistic, which PhillipsPerron uses with test_type="rho" and mackinnonp returns with dist_type="adf-z", is now a smooth and increasing function of the statistic. It is approximated by one polynomial below a cut-off and another above it. These were estimated separately, so the p-value jumped down at the cut-off, by 0.033 with "n", 0.014 with "c", 0.010 with "ct" and 0.008 with "ctt". The two are now estimated jointly, so that they have the same value and slope at the cut-off. The approximation of the middle of the distribution is also more accurate: the largest difference from the simulated distribution is now 0.012 with "n" and at most 0.0015 otherwise. Compared with 8.0, with a constant or a trend, p-values below 0.15 change by at most 0.0001, and the largest change is 0.013, at p-values between 0.7 and 0.8. The critical values are unchanged (GH989).

    • Integer, unsigned integer and Boolean data are now converted to float64 when they are passed to an estimator, so that no calculation is done in integer arithmetic. Previously a calculation that used the products or differences of integer data could overflow, wrap around or lose precision. For example, the kernel covariance estimators and cov_nw computed the sums of squares of int64 data with values near 2**32 in int64 when center=False or demean=False; ADF, VarianceRatio, DynamicOLS and FullyModifiedOLS took the differences of uint8 data, which wrap around below 0; and FixedVariance took the square root of uint8 variances in float16. All of these now give the same result as the same data stored as float64, which is passed through without a copy. The data of the bootstraps are not converted, since they are passed to the function of the user as given (GH948).

      The same rules for the data type apply to all of the estimators, the tests, the models, the volatility processes and the distributions. Integer, unsigned integer, Boolean, float32 and longdouble data are converted to float64, and every calculation is done in float64, so the result for float32 data is the result for the same values stored as float64. float32 is promoted because a calculation in float32 is not accurate enough: when all of the arrays of the unit root tests are float32, the Phillips-Perron statistic of a series with a large level differs from its float64 value by up to 0.04, and the lag search of ADF fails with a singular matrix for a series with a large level or a trend and thousands of observations. float16 data are never accepted: they raise a TypeError that names the argument and the accepted data types, and can be converted using astype(np.float32) or astype(np.float64). Complex data also raise a TypeError, except for the functions that estimate a Hermitian covariance (see the entry about complex data). The fixes of the covariance estimators and of the axis of cov_nw, and the first support of float32 and complex data in the covariance estimators, were contributed by antonsoo (GH942, GH943, GH957).

    • The kernel covariance estimators in arch.covariance.kernel and cov_nw accept complex data, and estimate the Hermitian long-run covariance. The products use the conjugate transpose, so that the lag-j autocovariance is the sum of x[t] times the conjugate of x[t - j], the automatic bandwidth uses the real part of the autocovariances of the complex series, and the estimates are Hermitian complex128 matrices with a real diagonal. For z = a + ib the long-run covariance is the covariance of a plus the covariance of b plus i times the cross-covariance of b and a less that of a and b, computed from the real data of a and b with the same kernel and bandwidth. The pseudo-covariance, which has no conjugate, is not estimated. cov_nw returns a real float for a 1-d complex series. In 8.0 the kernel estimators failed for complex data, and cov_nw had no conjugate, so that its result was not Hermitian. add_trend also accepts complex data, and adds real trend columns to them. The apply, cov and var of the bootstraps accept a statistic that returns complex values: cov is the Hermitian covariance and var is real, where the imaginary part used to be discarded with a ComplexWarning. conf_int raises a TypeError for a complex statistic, which has no interval. PreWhitenedRecolored, the tests and the models do not accept complex data, since there is no single model of complex data for the VAR that prewhitens the data. Thanks to antonsoo for the support of complex data in the covariance estimators that this builds on (GH942, GH957).

    • fit ignores starting_values that violate the bounds or constraints of the model, with the StartingValueWarning that was always issued. In previous versions the optimization was still started from the invalid values. Such fits start from the values constructed by the model and can converge to different estimates. Values with the wrong length or with NaN or inf now raise (see “Backward-incompatible changes”). The first_obs, last_obs and start of fit, fix and forecast now accept datetime.date and pandas.Period values and a pandas.PeriodIndex. A date or Period was silently ignored in previous versions, so the whole sample was used and forecast only forecast the last observation, and now the requested sample is used (GH925).

    • Fixed DynamicOLS with method in upper case. The method was validated in lower case but compared in its original case, so that "AIC" and "HQIC" selected the leads and lags using BIC, and now select them using the criterion that was requested (GH947).

    • Fixed APARCH.starting_values with common_asym=True and o > 1, which ranked the candidate starting values using the likelihood at the wrong parameters (the betas were taken from the positions of the gammas). The starting values, and so the estimates, of these models can change (GH949).

    • MCS now includes a model in included if its p-value is greater than or equal to size (previously strictly greater), and lists it in excluded only if the p-value is less than size (previously less than or equal). A model is in the model confidence set of size alpha if its MCS p-value is at least alpha. Bootstrap p-values are multiples of 1 / reps, so a p-value equal to size occurs in practice and the model was previously excluded (GH944).

    • The simulation and bootstrap forecasts of FIGARCH add the terms of the ARCH(\(\infty\)) representation in a different order, so that, given the same random numbers, the simulated variances, shocks and forecasts can differ from those of earlier versions in the last bits. The largest relative differences measured are about 1e-15. Analytic forecasts, estimates and the log-likelihood are unchanged (GH940).

    • The standard errors, t-statistics, p-values and param_cov of ARX models with a DataFrame of exogenous regressors differ from those of 8.0 in the fifth to seventh significant digit (up to 4e-5, relative), because the regressors are now passed to the compiled code as a C-contiguous array. The parameters and the log-likelihood are unchanged (GH674).

    Backward-incompatible changes¶

    • The bootstrap attribute of SPA, StepM, RealityCheck and MCS is now a read-only property. Assigning a bootstrap to an existing instance raises AttributeError, since quantities that depend on the bootstrap are computed when the instance is created. Create a new instance to use a different bootstrap (GH882).

    • nested=True with studentize=False in SPA and StepM raises a ValueError. The combination was accepted in previous versions (GH882).

    • block_size of CircularBlockBootstrap, MovingBlockBootstrap and StationaryBootstrap is now a read-only property, and setting it raises an AttributeError. In previous versions the attribute could be set, but the stationary bootstrap ignored the new value when sampling and clone, which is used for the nested bootstrap of studentized confidence intervals, used the value passed to the constructor. Create a new bootstrap to use a different block size (GH944).

    • std_err_func in conf_int no longer receives the params and state keywords that are used to simulate data when sampling is "semi-parametric" or "parametric". It is called as std_err_func(params, *args, **kwargs), where params is the estimate and kwargs contains only the data and extra_kwargs. Previously a std_err_func with a first argument named params raised a TypeError for these samplers (GH916).

    • The type keyword argument of hedgehog_plot() has been removed. See “Deprecations and removals” (GH945).

    • fit raises a ValueError for a cov_type other than "robust" or "classic" (in any case). Previously any other value, such as "White" or "mle", was silently treated as "classic" unless the model has a closed-form estimator, and the results reported the unknown value (GH925).

    • first_obs, last_obs and start of fit, fix and forecast must be an integer position in [-nobs, nobs], a date inside the index, or None. A float such as first_obs=10.0, a Boolean or a list raises a TypeError (they were silently ignored, so the whole sample was used), and a position or date outside the sample raises a ValueError: fit(first_obs=-1000) recorded -1000 as fit_start, fit(last_obs=10**6) recorded 10**6 as fit_stop, and forecast(start=10**6) failed with “negative dimensions are not allowed”. A string or date used with data that have no DatetimeIndex or PeriodIndex raises a ValueError, where it was an AssertionError (GH925, GH949).

    • Every public function, constructor and method now checks its arguments when it is called or created, before any computation. An error names the argument, says what is accepted and shows the value received, for example reps must be an integer >= 1; got 0 (int). A value of the wrong type raises a TypeError and a value that is not allowed (outside its range, not one of the options, of the wrong shape or length, or NaN or inf where finite values are needed) raises a ValueError. Integer arguments must be Python or NumPy integers: floats, including 5.0, and Booleans are rejected. Flags must be bool, np.bool_ or the integers 0 and 1: "no", None and 2 were accepted before and used for their truth value. NaN and inf in data raise, except where they are handled by design (the data of the bootstraps, which are passed to the function of the user, the diagnostics that drop NaN, and the residuals of a fitted model). Code that relied on the earlier behavior needs to change. The entries below list the calls that are affected, and the policy is described in the contributing guide (GH949, GH956).

    • Flags accept bool, np.bool_ and the integers 0 and 1 (Python and NumPy integers), which are converted to bool. This applies to every argument that the entries on the validation of arguments call a bool. An integer other than 0 and 1 raises a ValueError, and a float (including 1.0), a string, an array and None raise a TypeError, except that None is accepted where it is the documented default (low_memory and rescale). The disp of fit is "off", "final" or a flag, so that disp=0 is "off" and disp=1 is "final". The exit and append of arch.test are now checked as flags (GH956).

    • The unit root tests (ADF, DFGLS, PhillipsPerron, KPSS, VarianceRatio and ZivotAndrews) check all of their arguments when the test is created, including the length of the series against lags and max_lags. lags=2.5 (truncated to 2), lags="2" and lags=True raise a TypeError, and a negative lags or max_lags a ValueError (KPSS still accepts lags=-1). low_memory, debiased, robust and overlap must be bool (low_memory also accepts None). NaN or inf in the data raise ValueError: y must be a 1-d array of finite numbers; got 1 NaN (ndarray), where ADF, DFGLS and ZivotAndrews raised LinAlgError, PhillipsPerron statsmodels’ MissingDataError, KPSS a ValueError about converting NaN, and VarianceRatio returned NaN. The same applies to auto_bandwidth() (GH949).

    • The unit root tests no longer return a statistic that cannot be estimated. A regression in ADF or DFGLS with as many parameters as observations used to return a statistic of 0.0 because the residual degrees of freedom were 0, for example ADF(y[:14], lags=8).stat. An ADF with lags lags and k trend terms now needs at least 3 + 2 * lags + k observations, and DFGLS needs 3 + 2 * lags. A max_lags that is too large for the series, which raised LinAlgError or an error from statsmodels, now raises InfeasibleTestException when the test is created. The messages of this exception name the test, y and the number of observations (the messages of PhillipsPerron, KPSS and VarianceRatio said that an “ADF” could not be run) (GH949).

    • InfeasibleTestException, which the unit root tests raise if the series is too short or the specification cannot be estimated, is now also a ValueError. It is still a RuntimeError, so code that catches either keeps working (GH949).

    • The cointegration tests and estimators (engle_granger(), phillips_ouliaris(), DynamicOLS, FullyModifiedOLS and CanonicalCointegratingReg) check y and x when they are called. y must be 1-d and x 1-d or 2-d with at least one column, both finite, with the same number of rows and, for pandas objects, the same index. NaN or inf raise a ValueError (DynamicOLS accepted them, and the others raised LinAlgError, MissingDataError or a ValueError about converting NaN), y=None raises a TypeError, and the sample must have at least two more observations than the regression has parameters, where shorter samples raised ZeroDivisionError or LinAlgError or returned a statistic computed without residual degrees of freedom (GH949).

    • The lags, max_lags of engle_granger, and the lags, leads, max_lag and max_lead of DynamicOLS must be integers (lags=2.5, "2" and True were accepted). DynamicOLS(lags=-1) ran and estimated a model without the contemporaneous difference of x, and lags=150 on 100 observations failed with “zero-size array to reduction operation”; the four arguments must now be integers from 0 to nobs - 2, and the sample that remains after the differences, lags and leads must be larger than the number of parameters. The bandwidth of the cointegration estimators must be a finite real number of at least 0 or None (bandwidth=True ran as 1), and low_memory, force_int, diff, df_adjust, common and similar flags must be bool ("yes" and None were accepted). The error for an invalid x_trend is raised when the object is created and names x_trend (GH949).

    • The arguments of the kernel covariance estimators in arch.covariance.kernel, PreWhitenedRecolored and cov_nw are checked when the object is created or the function is called. df_adjust=2.5 was truncated to 2, a Boolean was used as 0 or 1 for df_adjust and bandwidth, and floats, including 5.0, are no longer accepted for df_adjust, lags, max_lag, axis and ddof. center, force_int, diagonal, sample_autocov and demean must be bool. NaN or inf in x (or in y of cov_nw), which returned NaN covariances, and in weights raise a ValueError, as PreWhitenedRecolored already did. A negative lags in cov_nw, a non-integer axis such as nan or 1.0 (which selected axis 0), and a ddof that is negative or equal to the number of observations (which divided by zero and returned inf) raise an error, and so do bandwidth=nan and bandwidth=inf of QuadraticSpectral and ZeroLag. NumPy Booleans are accepted for every flag (PreWhitenedRecolored(x, center=np.True_) raised a TypeError) (GH949).

    • The arguments of the bootstraps (IIDBootstrap, IndependentSamplesBootstrap, CircularBlockBootstrap, MovingBlockBootstrap and StationaryBootstrap) and of optimal_block_length() are checked when the object is created or the method is called. seed=True (used as 1), reps=0 (apply(reps=0) returned an empty array and bootstrap(reps) yielded no replications), reps=True, conf_int(size=True), a flag that is not bool (reuse, recenter, use_seed), block_size=True, a studentize_reps that is not an integer, an extra_kwargs that is not a dictionary, a bootstrap with no data and an input with no rows (which gave NaN results) now raise. optimal_block_length raises for NaN or inf, a scalar and fewer than 11 observations. A moving block bootstrap with a block longer than the data raises a ValueError that names block_size. Setting state to a value of the wrong type raises a TypeError and not an AssertionError (GH949).

    • The arguments of MCS, SPA, RealityCheck and StepM are checked when the object is created. MCS(size=nan), MCS(size=2) and MCS(size=-1) ran, and size must be a number in (0, 1) for MCS and StepM. reps=0 gave NaN p-values in SPA and RealityCheck, and reps must be an integer that is at least 1. studentize and nested must be bool. block_size must be an integer between 1 and the number of observations. benchmark and models with different numbers of rows, a benchmark with several columns, and fewer than three observations (one or two gave NaN warnings) raise a ValueError. SPA.subset needs a Boolean selector of the right length with at least one True, and the arguments of critical_values and better_models are checked before the “compute must be called” error (GH949).

    • The arguments of fit(), fix() and compute_param_cov() are checked when the method is called. A negative or NaN tol (tol=0 is still accepted), a backcast that is NaN or inf, a negative update_freq (treated as 0), a show_warning that is not bool ("no" was accepted), a disp that is neither a string nor a bool, options that is not a mapping, and params of fix with the wrong length or with NaN or inf now raise. fit(starting_values=...) raises a ValueError if the starting values do not have one finite element for each parameter (a wrong length raised an error from NumPy, and NaN gave estimates of NaN), and a TypeError if they cannot be converted to numbers. fit raises a ValueError if the model has more parameters than the number of observations used to estimate it: GARCH(p=300) on 250 observations ran for minutes and now fails at once. There is no limit on the lags of a model that has fewer parameters, or on the truncation of FIGARCH (GH949).

Arguments of arch_model that do not apply to the selected model are still ignored (GH949).

The error for parameters outside the bounds in cdf, ppf and the moments names the parameter, for example parameters[0] (nu) must be a finite float in [2.05, 500]; got 1.0 (float), where it named the first letter of the name of the distribution (GH949).

An argument of the wrong type now raises a TypeError where it raised a ValueError, an AssertionError, a KeyError or an AttributeError: examples are horizon=3.0 of forecast, lags of MAMean, truncation="apple" of FIGARCH, p=1.0 of arch_model, extra_kwargs="abc" of the bootstraps, df_adjust that is not an integer and lags of PreWhitenedRecolored that is not an integer. Earlier versions converted them to float64 in some places and failed with an error from NumPy in others. The 11 bits of float16 are about 3 decimal digits, which is not enough for these estimators, and the message names the accepted data types. Convert the data with astype(np.float32) or astype(np.float64) if that is intended. Complex data raise a TypeError too, except in the kernel covariance estimators, cov_nw, add_trend and the apply, cov and var of the bootstraps (GH957).

The values only differ when a partial sum is below the lower bound or above the upper bound of the variance. The pure Python updater was correct (GH940).

    • Fixed the methods of the volatility processes so that an argument that cannot be used by the compiled recursions raises an error instead of ending the interpreter or reading and writing memory that does not belong to the array. For example, GARCH().compute_variance(None, resids, sigma2, backcast, var_bounds), and None for sigma2 or var_bounds, ended the Python process, an empty sigma2 damaged the heap, and a sigma2, resids, var_bounds or parameters of the wrong length was read or written out of bounds. compute_variance of every volatility process now checks that parameters has num_params elements, that resids is a vector, that sigma2 is a writeable float64 vector with the length of resids and that var_bounds has a row of two columns for each residual. simulate and forecast check the length of parameters, which silently accepted extra elements such as the parameters of the distribution (GH949).

    • Fixed crashes of the interpreter, and reads and writes outside of an array, when the recursions were called directly with missing or too short arrays. The initialize_update methods of the implementations of VolatilityUpdater (GARCH, HARCH, EWMA, MIDAS, FIGARCH, FIAPARCH and EGARCH) and ARCHInMeanRecursion.recursion now raise a TypeError for None and a ValueError for an array that is too short, as the pure Python versions do. The FIGARCH and FIAPARCH updaters require an integer truncation of at least 1, and the HARCH updater rejects lags=None, which computed a model without lags. The models were not affected, since they check these values before they call the recursions (GH951).

    • Fixed the functions that look up critical values and p-values in arch.unitroot.unitroot. mackinnonp and mackinnoncrit with num_unit_roots=0 or -1 silently used the last row of the table (mackinnonp(-3.0, num_unit_roots=-1) gave 0.5876), mackinnonp with 7 or more unit roots raised an IndexError although the documentation said that 12 were available, mackinnoncrit(nobs=0) raised a ZeroDivisionError, and mackinnoncrit(3, dist_type="adf-z") ignored num_unit_roots. num_unit_roots must now be an integer between 1 and 6 for mackinnonp and between 1 and 12 for mackinnoncrit, nobs must be positive, and stat cannot be NaN. mackinnoncrit(nobs=inf) returned a view of the table of critical values, so that changing the result changed the critical values of every later call and test in the process, and it now returns a copy. kpss_crit(-1) returned a p-value of 1.0 and kpss_crit(nan) returned NaN, and they now raise a ValueError. mackinnonp with dist_type="dfgls" raises a ValueError for the "n" and "ctt" regressions, which are not available, where it raised a KeyError (GH949).

    • The unit root tests (ADF, DFGLS, PhillipsPerron, KPSS, ZivotAndrews and VarianceRatio), the cointegration tests engle_granger() and phillips_ouliaris(), and DynamicOLS, FullyModifiedOLS and CanonicalCointegratingReg raise an InfeasibleTestException, which is also a ValueError, when y is constant. The unit root tests raise it when they are created. Previously they returned NaN, raised a ZeroDivisionError or a LinAlgError, or, for a constant that is not 0, computed the statistic and the p-value from the rounding errors of removing the mean. For example KPSS rejected stationarity with a p-value of 0.0001, and engle_granger() and phillips_ouliaris() returned arbitrary statistics. They also raise it, where they returned NaN or raised LinAlgError or ValueError, when the statistic or its p-value, or the estimates or their covariance, are not finite or a matrix is singular, which data at an extreme scale such as 1e300 or 1e-300 produce. For example the statistics of ADF, PhillipsPerron and VarianceRatio of a random walk multiplied by 1e300 were NaN, and KPSS raised ValueError: cannot convert float NaN to integer. They raise it too when a regression is exactly singular, which statsmodels only warned about with SingularMatrixWarning, or fits exactly, which gave statistics computed from rounding errors: when y is exactly a trend that the test removes (a linear trend with trend="ct" and a quadratic trend with trend="ctt"), when the differences of y are exactly a deterministic function of its lags, as for the series 0, 1, 0, 1, …, or when y is an exact linear combination of x and the deterministic terms or the columns of x are collinear. For example ADF with trend="ct" of a linear trend was 1.9e14, and KPSS and DFGLS with trend="ct" rejected their null hypotheses for it (GH987).

    • PhillipsPerron with trend="c" or trend="ct" computes its statistic from y less its mean, on which it does not depend. A variation that is small compared with the level of y lost precision, so that a random walk with steps of 1e-6 around 1000 had a statistic of -150 where the same walk has -2.67. The results in PhillipsPerron.regression are still those of the regression of y (GH987).

    • Fixed SkewStudent.ppf for a 0-d array such as np.array(0.4), which failed an assert (it returns a float, as for a Python float), and add_trend with a DataFrame that already has a constant and has_constant="skip" (the default) for trend "c", "ct" and "ctt", which raised ValueError: Shape of passed values is (4, 1), indices imply (4, 2) (GH949).

    • Fixed cov_nw so that a negative axis is interpreted as in NumPy (axis=-1 gave the result of axis=0) and an axis that is out of range always raises a ValueError. Contributed by antonsoo (GH943, merged in GH948).

    • The starting_values, backcast and compute_variance methods of the volatility processes and the loglikelihood methods of the distributions raised an error for integer arrays, and for lists. add_trend failed on Boolean data. A Series without a name that is passed by the user, for example to arch_model(), is no longer renamed to the string "None" (GH948).

    • Fixed the bootstraps of a statistic that returns the same array in every call, for example one that writes its result with NumPy’s out= argument. The estimate of the original sample and the jackknife estimates were overwritten by later calls, which shifted the confidence intervals, changed cov and var and could make BCa raise an error. They are now copied. Contributed by antonsoo (GH954).

    • Fixed partial_moment of StudentsT for odd orders when nu is 342 or more, which returned 0. For example the first partial moment at 0 with nu=342 is -0.39865. The partial moments of Normal and StudentsT of order 2 or more at -inf and inf, which were NaN, are 0 and the moment of that order. Contributed by mkzung (GH969, GH970, GH985).

    • Small p-values are no longer rounded to 0. The p-value of WaldTestStatistic, which the ARCH LM test and other tests return, the p-value of VarianceRatio and the pvalues of the results of DynamicOLS, FullyModifiedOLS and CanonicalCointegratingReg were computed as 1 minus a CDF, which is 0 for p-values smaller than about 1e-16. For example the p-value of a Wald statistic of 100 with 2 degrees of freedom was 0 and is 1.9e-22. Contributed by galafis (GH975, GH977).

    • superior_models returns Python integers for the models that are found after the first step, which were NumPy integers. Contributed by wavebyrd (GH974).

    • Fixed add_trend for a DataFrame with a duplicated index, which multiplied the rows and mixed the trend values of different observations. The trend columns are now added by position. Contributed by jackiectl2 (GH978).

    • Object data, including object Series and DataFrame columns, whose elements are complex numbers with imaginary parts that are all 0 are converted to float64, as for real numbers. They were rejected unless complex data are allowed, and were then complex128. Contributed by galafis (GH976, GH982).

    • The automatic bandwidth of the kernel covariance estimators and of PreWhitenedRecolored raises a ValueError for data in which every column is constant, as bandwidth_method="andrews" does, where it raised a ZeroDivisionError (GH985).

    • mackinnonp returns 0 for a statistic of -inf and 1 for inf, where it returned NaN for the ADF-Z tables and for the ADF test without a trend, and no longer warns about an overflow for a very large statistic (GH985).

    Performance¶

    • Automatic lag selection in DFGLS no longer estimates an ADF test whose result was discarded, which makes it several times faster (GH890). Contributed by ZacKienzle2.

    • MCS no longer copies the resampled losses in each bootstrap replication (GH895). Contributed by ZacKienzle2.

    • The long-run variance of the loss differentials that SPA and StepM use when nested=False is computed using an FFT, which makes studentize=False about twice as fast as in previous versions (GH882).

    • Evaluating the variance recursions of FIGARCH, HARCH and MIDASHyperbolic models is about 3, 4 and 1.4 times faster with the compiled recursions, so that estimating a FIGARCH model with the default truncation of 1000 is about 2.5 times faster. Simulating from HARCH and MIDASHyperbolic models is 3 to 30 times faster, and the multi-step analytic forecasts of ARCH and GARCH models are computed for all forecast origins at once, which makes forecasting every observation of a sample of 5000 observations 10 steps ahead about 80 times faster (GH940).

    • The simulation and bootstrap forecasts of FIGARCH compute the contribution of the observed history once for each forecast origin and horizon, and not once for each simulated path. Forecasting 100 origins 10 steps ahead using 1000 paths and a truncation of 1000 is about 20 to 30 times faster (GH940).

    Compatibility¶

    • Python 3.10 to 3.15 are supported, and wheels are available for Linux (manylinux on x86-64 and aarch64, and musllinux on x86-64), Windows (AMD64) and macOS (arm64 and x86-64) for each of them. 9.0 is the last release that supports Python 3.10 and NumPy 1.x. Later releases will raise the other minimum versions accordingly.

    • Building from source requires Cython 3.1.0 or later.

    • Running the test suite requires pytest 9 or later.

    • Improved compatibility with current and upcoming releases of NumPy and pandas: the warning of pandas 3.1 for time zone aware indices in date lookups is fixed, and the code no longer sets the shape of arrays (GH842, GH912).

    • The minimum versions of Python (3.10), NumPy (1.22.3), SciPy (1.8) and pandas (1.4.0) have not changed. Building from source requires Cython 3.1.0, and running the tests requires pytest 9.
