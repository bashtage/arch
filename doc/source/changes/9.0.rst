=========
Version 9
=========

Release 9.0 (Unreleased)
========================

Highlights
~~~~~~~~~~
- :class:`~arch.bootstrap.SPA` and :class:`~arch.bootstrap.StepM` now studentize the
  loss differentials when ``studentize=True``, which is the default. The option had
  no effect in previous versions, and so p-values, critical values and the superior
  models obtained using the default arguments differ from previous versions. Use
  ``studentize=False`` for the previous statistics.
- Added :class:`~arch.univariate.FIAPARCH`, a fractionally integrated asymmetric
  power ARCH volatility process (contributed by gjunjie).
- Added :class:`~arch.univariate.MAMean`, a moving average mean model that can be
  used with any volatility process and distribution (contributed by premdev1234).
- Added :meth:`~arch.univariate.base.ARCHModel.append`, which adds observations to a
  mean model in-place so that parameters estimated using earlier data can be used to
  produce forecasts without re-estimating the model.
- Added :class:`~arch.covariance.var.PreWhitenedRecolored`, which implements the
  VAR-HAC and pre-whitened recolored long-run covariance estimators (contributed by
  WatchTree-19).
- Added Ng and Perron's modified AIC, ``method="maic"``, for selecting the number of
  lags in the :class:`~arch.unitroot.ADF`, :class:`~arch.unitroot.DFGLS` and
  :class:`~arch.unitroot.ZivotAndrews` tests.
- Wheels are available for Python 3.10 to 3.15. 9.0 is the last release that
  supports Python 3.10 and NumPy 1.x.

New features
~~~~~~~~~~~~
- Added :class:`~arch.univariate.FIAPARCH`, a fractionally integrated asymmetric
  power ARCH volatility process that extends :class:`~arch.univariate.FIGARCH` with
  an asymmetry parameter and a power parameter, ``delta``, which is estimated
  unless a value is provided. The orders ``p``, ``o`` and ``q`` can be 0 or 1. It
  can be used in :func:`~arch.univariate.arch_model` with ``vol="FIAPARCH"``.
  Analytic forecasts are only available for a horizon of 1, and longer horizons
  require ``method="simulation"`` or ``method="bootstrap"``. Contributed by
  gjunjie.

.. TODO(R2): hold-a90-bug2a-fiaparch-backcast (decision 35). FIAPARCH is new in 9.0,
   so the fix to the backcast used with an estimated ``delta`` needs no entry. Only
   check that the FIAPARCH bullet above is still accurate once the fix has merged.

- Added :class:`~arch.univariate.MAMean`, a moving average mean model of order q
  with an optional constant that can be used with any volatility process and
  distribution. Analytic, simulation and bootstrap forecasts include the moving
  average terms for the first q steps. It is a class only: ``arch_model`` does not
  support ``mean="MA"``. Contributed by premdev1234.
- Added :meth:`~arch.univariate.base.ARCHModel.append` to the mean models, which
  adds new observations to a model in-place. Parameters estimated using earlier
  data can then be used to produce forecasts, or results using
  :meth:`~arch.univariate.base.ARCHModel.fix`, without re-estimating the model. The
  new data must have the same type as the data used to construct the model, and
  models that include exogenous regressors require ``x`` for the new observations.
- Added :class:`~arch.covariance.var.PreWhitenedRecolored`, which implements the
  VAR-HAC (den Haan and Levin) and pre-whitened recolored (Andrews and Monahan)
  long-run covariance estimators, and the :class:`~arch.covariance.kernel.ZeroLag`
  kernel that it uses for VAR-HAC. The order, residuals and residual covariance of
  the VAR are available as ``order``, ``resid`` and ``resid_cov``. Contributed by
  WatchTree-19.
- Added the residual diagnostics :func:`~arch.univariate.excess_kurtosis`,
  :func:`~arch.univariate.hill_estimator` and :func:`~arch.univariate.var_ratio`,
  which use standardized residuals. The results of a model also have
  :attr:`~arch.univariate.base.ARCHModelResult.excess_kurtosis`,
  :meth:`~arch.univariate.base.ARCHModelResult.hill_estimator` and
  :meth:`~arch.univariate.base.ARCHModelResult.var_ratio`, which use the
  standardized residuals and the estimated distribution of the model.
- Added ``method="maic"`` to the automatic lag selection of
  :class:`~arch.unitroot.ADF`, :class:`~arch.unitroot.DFGLS` and
  :class:`~arch.unitroot.ZivotAndrews`. It selects the lag that minimizes the
  modified AIC of Ng and Perron (2001).
- Added the keyword argument ``low_memory`` to
  :func:`~arch.unitroot.cointegration.engle_granger`, which is passed to the
  :class:`~arch.unitroot.ADF` test of the residuals. The default, ``None``, selects
  the lag selection algorithm automatically.
- Kernel names are now looked up in one place,
  ``arch.covariance.kernel.get_kernel_estimator``, using the list
  ``arch.covariance.kernel.KERNELS``. All estimators that take a ``kernel`` accept
  the same names, in any case and with hyphens or underscores ignored, and raise
  the same error, which lists the available kernels, for an unknown name. As a
  result, the ``fit`` methods of
  :class:`~arch.unitroot.cointegration.FullyModifiedOLS` and
  :class:`~arch.unitroot.cointegration.CanonicalCointegratingReg` accept names such
  as ``"quadratic-spectral"``, which raised ``KeyError`` in previous versions.
- Automatic lag selection in :class:`~arch.unitroot.DFGLS` no longer estimates an
  :class:`~arch.unitroot.ADF` test whose result was discarded, which makes it about
  three times faster.
- :class:`~arch.bootstrap.MCS` no longer copies the resampled losses in each
  bootstrap replication.
- The long-run variance of the loss differentials that :class:`~arch.bootstrap.SPA`
  and :class:`~arch.bootstrap.StepM` use when ``nested=False`` is computed using an
  FFT, which makes ``studentize=False`` about twice as fast as in previous versions.

Changes that alter results
~~~~~~~~~~~~~~~~~~~~~~~~~~
These changes fix bugs that returned incorrect results, or make an option that had
no effect work as documented. Each entry says who is affected and, where there is
one, how to restore the previous results.

- Fixed :class:`~arch.bootstrap.SPA` and :class:`~arch.bootstrap.StepM` so that
  ``studentize=True`` (the default) studentizes the loss differentials. In
  previous versions the option had no effect on the results. The loss
  differentials are now studentized in the original data and inside each
  bootstrap replication, using the standard error from a kernel long-run
  variance estimator that matches the bootstrap, or from a nested bootstrap
  if ``nested=True``. Everyone who uses the default arguments is affected:
  p-values, critical values and the superior models differ from previous versions,
  and the critical values apply to the studentized mean loss differentials, so
  code that compares ``critical_values`` with mean loss differentials or that uses
  fixed thresholds must change. For example, with 1000 observations, 12 models of
  which 3 are better than the benchmark and ``reps=1000``, the lower, consistent and
  upper p-values change from 0.102, 0.162 and 0.162 to 0 for all three, the 5%
  consistent critical value changes from 0.173 to 2.52, ``better_models`` changes
  from empty to the three better models, and the ``superior_models`` of
  :class:`~arch.bootstrap.StepM` with ``size=0.10`` change from no models to four
  models. When the evidence is weak the p-values can move in either direction. Use
  ``studentize=False`` for the statistics that were always used in previous
  versions. Studentizing in each replication makes the default about 2.2 times
  slower (for 2000 observations, 100 models and 1000 replications, 1.35 seconds in
  previous versions and 2.99 seconds now).
- ``nested=True`` in :class:`~arch.bootstrap.SPA` and
  :class:`~arch.bootstrap.StepM` now computes the variances used to studentize
  in every bootstrap replication using a nested bootstrap, and not only in the
  original data, and never uses the kernel estimator. The run time grows with the
  square of ``reps``: with 500 observations, 10 models and 200 replications it
  increased from 0.04 seconds to 3.2 seconds. ``nested=True`` requires
  ``studentize=True`` and raises a ``ValueError`` otherwise, so there is no way to
  restore the previous statistics with ``nested=True``.
- When ``nested=False``, the long-run variances in
  :class:`~arch.bootstrap.SPA` and :class:`~arch.bootstrap.StepM`, which are
  used to select the models that are re-centered when computing the consistent
  p-value, now use the kernel that matches the bootstrap. Previously they
  always used the stationary bootstrap kernel, so the consistent p-value can
  also change with ``studentize=False`` when using the circular or moving
  block bootstraps. Results of the stationary bootstrap do not change. In the
  examples that were checked the effect on the critical values was small: the 5%
  consistent critical value of the circular bootstrap changed from 0.1453 to
  0.1391 (-4%), and the 10% value of the moving block bootstrap from 0.1235 to
  0.1138 (-8%).
- Fixed the simulation and bootstrap forecasts of
  :class:`~arch.univariate.RiskMetrics2006`. The simulated paths started from the
  variance at the forecast origin instead of the one-step-ahead variance, and so
  the forecast of the first step differed from the analytic forecast and the
  error carried into longer horizons. Analytic forecasts, estimation and ``fix``
  are not changed. For example, for a zero mean model of daily S&P 500 returns,
  the simulated variance of the first step at the last origin changes from 3.048
  to 2.774 (-9%), which is the analytic forecast, and for a constant mean model of
  NASDAQ returns with Student's t errors it changes from 3.383 to 5.462 (+61%) at
  one origin when the volatility had just increased.

- Fixed the acceleration constant of BCa confidence intervals computed by
  :meth:`~arch.bootstrap.IIDBootstrap.conf_int` when the function returns more than
  one statistic. The jackknife estimates of each statistic were centered at the
  mean of the estimates of all of the statistics, and not at their own mean, which
  changed the intervals when the statistics are at different levels. Intervals of a
  function that returns one statistic are not changed. For example, for the column
  means of data with columns at levels near 3 and 103, the intervals changed from
  [2.4114, 2.9856] and [102.6764, 103.4099] to [2.4184, 2.9871] and
  [102.6954, 103.4222], which now equal the intervals from bootstrapping each
  column alone. Typical endpoint changes are 0.2% to 3%.
- Fixed the residuals and conditional volatility of :class:`~arch.univariate.ARCHInMean`
  results. In previous versions ``resid``, ``conditional_volatility``, ``std_resid``
  and ``rsquared``, and the quantities derived from them such as the output of
  ``summary`` and ``arch_lm_test``, were computed as if the in-mean parameter
  ``kappa`` was 0, so they did not match the log-likelihood. They now use the
  same recursion as the log-likelihood, for all values of ``form`` and for both
  ``fit`` and ``fix``. The estimated parameters, log-likelihood and standard
  errors are unchanged. The values change whenever ``kappa`` is not 0. For
  example, for a GARCH(1,1) model with one AR lag fit to the daily S&P 500
  returns in ``arch.data.sp500``, the conditional volatility changes by at most
  3.7% (``form="log"``), 5.1% (``"vol"``) and 6.1% (``"var"``), the largest
  change in a residual is 0.15, 0.53 and 1.1, and R-squared changes from
  0.0021 to 0.0021, from 0.0039 to 0.0012 and from 0.0047 to -0.0006.
  R-squared can now be negative for these models.

- Fixed ``conf_int`` with ``sampling="semi-parametric"`` or ``sampling="parametric"``
  in the bootstrap classes in :mod:`arch.bootstrap`. In previous versions the
  ``params`` (and ``state``) keywords used to simulate the data were added to the
  data of the bootstrap, so ``method="studentized"`` raised an error when the
  studentization used a nested bootstrap. When ``extra_kwargs`` was also given, the
  nested bootstrap silently used the non-parametric statistic. The nested bootstrap now
  simulates the data in the same way as the outer bootstrap, so studentized intervals
  from the nested bootstrap with these samplers change from previous versions.
- Fixed :class:`~arch.unitroot.cointegration.CanonicalCointegratingReg` so that
  ``df_adjust=True`` scales the entire estimate of the conditional long-run
  variance, as :class:`~arch.unitroot.cointegration.FullyModifiedOLS` does.
  Previously only the first term was scaled, which overstated the parameter
  covariance and ``long_run_variance`` when the regressors are endogenous. Results
  using the default, ``df_adjust=False``, are not changed. For example, in a
  regression with 100 observations and a bandwidth of 4, the standard errors with
  ``df_adjust=True`` were 9.5% larger than with ``df_adjust=False`` and are now
  1.6% larger, and ``long_run_variance`` was 20% larger and is now 3.1% larger. In
  regressions with about 400 observations the standard errors change by less than
  0.1%.
- Fixed :class:`~arch.unitroot.DFGLS` when the data are integers. The
  quasi-differenced data were truncated to integers, which produced a statistic and
  p-value that differ from those of the same data stored as floats. Results for data
  that are floats are not changed. For example, the statistic of one integer series
  changed from -0.3005 to -0.3378, and its p-value from 0.581 to 0.567. Convert the
  data to floats to obtain the previous statistic.
- Fixed :func:`~arch.unitroot.auto_bandwidth` so that the autocovariances are
  not truncated to integers. In previous versions any series with
  non-integer values could return an incorrect bandwidth or raise
  ``ZeroDivisionError``, which happened when all of the autocovariances were less
  than 1 in absolute value. For example, the bandwidths for the Bartlett, Parzen and
  quadratic spectral kernels of daily S&P 500 percent returns change by +1.7%, +1.5%
  and +0.5%, and the quadratic spectral bandwidth of the first difference of a bond
  yield series changes by +61%. Only :func:`~arch.unitroot.auto_bandwidth` is
  affected: the kernel classes, :class:`~arch.unitroot.PhillipsPerron` and
  :class:`~arch.unitroot.KPSS` do not use it.

Backward-incompatible changes
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
- The ``bootstrap`` attribute of :class:`~arch.bootstrap.SPA`,
  :class:`~arch.bootstrap.StepM` and :class:`~arch.bootstrap.MCS` is now a read-only
  property. Assigning a bootstrap to an existing instance raises ``AttributeError``,
  since quantities that depend on the bootstrap are computed when the instance is
  created. Create a new instance to use a different bootstrap.
- ``nested=True`` with ``studentize=False`` in :class:`~arch.bootstrap.SPA` and
  :class:`~arch.bootstrap.StepM` raises a ``ValueError``. The combination was
  accepted in previous versions.
- The exceptions raised for invalid input are different in several places, and some
  calls that were accepted now raise. See "Bug fixes" for details. The ones most
  likely to affect code are: :func:`~arch.univariate.arch_model` raises
  ``TypeError``, and not ``AssertionError``, for a ``p`` that is not an integer; the
  ``method`` of the unit root tests raises ``ValueError`` or ``TypeError`` with a
  different message;
  :meth:`~arch.univariate.base.ARCHModelResult.arch_lm_test` raises ``ValueError``
  when ``lags`` is less than 1, which was replaced by 1;
  :class:`~arch.bootstrap.MCS`, :class:`~arch.bootstrap.SPA` and
  :class:`~arch.bootstrap.StepM` raise ``ValueError`` when the losses contain ``NaN``
  or infinite values; and the ``block_size`` of the circular, moving block and
  stationary bootstraps and the ``method`` of :class:`~arch.bootstrap.MCS` are
  validated.
- ``std_err_func`` in ``conf_int`` no longer receives the ``params`` and ``state``
  keywords that are used to simulate data when ``sampling`` is ``"semi-parametric"`` or
  ``"parametric"``. It is called as ``std_err_func(params, *args, **kwargs)``, where
  ``params`` is the estimate and ``kwargs`` contains only the data and ``extra_kwargs``.
  Previously a ``std_err_func`` with a first argument named ``params`` raised a
  ``TypeError`` for these samplers.
- The ``type`` keyword argument of
  :meth:`~arch.univariate.base.ARCHModelResult.hedgehog_plot` has been removed. See
  "Deprecations and removals".

- ``block_size`` of :class:`~arch.bootstrap.CircularBlockBootstrap`,
  :class:`~arch.bootstrap.MovingBlockBootstrap` and
  :class:`~arch.bootstrap.StationaryBootstrap` is now a read-only property, and setting
  it raises an ``AttributeError``. In previous versions the attribute could be set, but
  the stationary bootstrap ignored the new value when sampling and ``clone``, which is
  used for the nested bootstrap of studentized confidence intervals, used the value
  passed to the constructor. Create a new bootstrap to use a different block size.

Bug fixes
~~~~~~~~~
- Fixed :class:`~arch.bootstrap.StepM`, which raised a ``ValueError`` when all of
  the models were found to be superior after more than one round of the procedure
  (:issue:`862`).
- Fixed the check that ``p`` is a scalar ``int`` in
  :func:`~arch.univariate.arch_model`, which only worked when ``vol`` was lower
  case. In other cases, including the default ``vol="GARCH"``, an
  ``AssertionError`` was raised for a ``p`` that is not an ``int``. A ``TypeError``
  is now always raised. Contributed by gjunjie.
- The ``method`` used to select the number of lags in :class:`~arch.unitroot.ADF`,
  :class:`~arch.unitroot.DFGLS` and :class:`~arch.unitroot.ZivotAndrews` is not case
  sensitive. In previous versions ``"AIC"`` and ``"BIC"``, which were the documented
  values, raised a ``ValueError``. ``"t"`` and ``"tstat"`` are accepted as aliases
  of ``"t-stat"``, a ``method`` that is not a string raises ``TypeError`` and an
  unknown ``method`` raises a ``ValueError`` that lists the valid choices.
- Fixed :class:`~arch.unitroot.ZivotAndrews`, which raised an exception when the
  data are integers.
- Fixed the ``trend`` property of the results of
  :func:`~arch.unitroot.cointegration.engle_granger`, which was always ``"c"``.
- The summary of the results of
  :class:`~arch.unitroot.cointegration.CanonicalCointegratingReg` now has the title
  "Canonical Cointegrating Regression" and not "Fully Modified OLS".
- Fixed :class:`~arch.univariate.ARCHInMean` models that include a constant, lags and
  exogenous regressors stored in a ``DataFrame``, which raised
  ``ValueError: ndarray is not C-contiguous`` when estimated.
- Fixed a ``TypeError`` when a timezone-naive ``Timestamp`` is used as ``first_obs``,
  ``last_obs`` or ``start``, for example in
  :meth:`~arch.univariate.base.ARCHModel.fit` and
  :meth:`~arch.univariate.base.ARCHModel.forecast`, with data that have a timezone
  aware index. The ``Timestamp`` is treated as the equivalent date string.
- Fixed :class:`~arch.bootstrap.MCS` with ``method="max"``, which could fail to
  terminate when the estimated standard deviation of a loss difference is 0, for
  example when two of the losses are identical. A ``RuntimeWarning`` is issued.

Compatibility
~~~~~~~~~~~~~
- Python 3.10 to 3.15 are supported, and wheels are available for Linux (manylinux
  on x86-64 and aarch64, and musllinux on x86-64), Windows (AMD64) and macOS (arm64
  and x86-64) for each of them. 9.0 is the last release that supports Python 3.10
  and NumPy 1.x. Later releases will raise the other minimum versions accordingly.
- Building from source requires Cython 3.1.0 or later.
- Running the test suite requires pytest 9 or later.
- The continuous integration now builds and tests the wheel on macOS (arm64 and
  Intel), and tests Python 3.10 to 3.15 with exact versions of the dependencies.
