=========
Version 9
=========

Release 9.0 (Unreleased)
========================

Highlights
~~~~~~~~~~
- :class:`~arch.bootstrap.SPA` and :class:`~arch.bootstrap.StepM` now studentize the
  loss differentials when ``studentize=True``, which is the default. The option had no
  effect in previous versions, and so p-values, critical values and the superior models
  obtained using the default arguments differ from previous versions. Use
  ``studentize=False`` for the previous statistics.
- Added :class:`~arch.univariate.FIAPARCH`, a fractionally integrated asymmetric power
  ARCH volatility process (contributed by gjunjie).
- Added :class:`~arch.univariate.MAMean`, a moving average mean model that can be used
  with any volatility process and distribution (contributed by premdev1234).
- Added :meth:`~arch.univariate.base.ARCHModel.append`, which adds observations to a
  mean model in-place so that parameters estimated using earlier data can be used to
  produce forecasts without re-estimating the model.
- Added :class:`~arch.covariance.var.PreWhitenedRecolored`, which implements the VAR-HAC
  and pre-whitened recolored long-run covariance estimators (contributed by
  WatchTree-19).
- Added :class:`~arch.univariate.NGARCH`, the nonlinear asymmetric GARCH of Engle and
  Ng, the VaR backtests of Kupiec and Christoffersen and the Basel traffic light, and
  :class:`~arch.bootstrap.LocalBlockBootstrap`, the local block bootstrap of
  Paparoditis and Politis.
- The automatic bandwidth of the kernel covariance estimators can use the AR(1)
  plug-in method of Andrews (1991) with ``bandwidth_method="andrews"``, and the default
  method of Newey and West (1994) now gives the bandwidths and estimates of the R
  package sandwich, which changes every automatic bandwidth. See "Changes that alter
  results".
- Added the residual diagnostics :func:`~arch.univariate.excess_kurtosis`,
  :func:`~arch.univariate.hill_estimator` and :func:`~arch.univariate.var_ratio`
  (contributed by albystack), and Ng and Perron's modified AIC, ``method="maic"``, for
  selecting the number of lags in the :class:`~arch.unitroot.ADF`,
  :class:`~arch.unitroot.DFGLS` and :class:`~arch.unitroot.ZivotAndrews` tests.
- Fixed bugs that change results. The most important are the studentization of
  :class:`~arch.bootstrap.SPA` and :class:`~arch.bootstrap.StepM`, the simulation and
  analytic forecasts of :class:`~arch.univariate.RiskMetrics2006`, the analytic
  forecasts of GJR-type models with skewed distributions, BCa confidence intervals of
  functions that return several statistics, :class:`~arch.univariate.ARCHInMean` models,
  :class:`~arch.unitroot.DFGLS` and :func:`~arch.unitroot.auto_bandwidth` with integer
  data, and the ADF-Z critical values and p-values without a trend, which
  :class:`~arch.unitroot.PhillipsPerron` uses with ``test_type="rho"``. See "Changes
  that alter results".
- The arguments of the public API are validated consistently. An invalid argument raises
  a ``TypeError`` (wrong type) or a ``ValueError`` (value that is not allowed) with a
  message that names the argument, shows the value and says what is accepted, the string
  options are not case sensitive, and integer, Boolean and list data are converted to
  ``float64``. Some calls that were accepted by earlier versions now raise. See
  "Backward-incompatible changes".
- Python 3.10 to 3.15 are supported, with wheels for each of them. 9.0 is the last
  release that supports Python 3.10 and NumPy 1.x.

New features
~~~~~~~~~~~~
- Added :class:`~arch.univariate.FIAPARCH`, a fractionally integrated asymmetric power
  ARCH volatility process that extends :class:`~arch.univariate.FIGARCH` with an
  asymmetry parameter and a power parameter, ``delta``, which is estimated unless a
  value is provided. The orders ``p``, ``o`` and ``q`` can be 0 or 1. It can be used in
  :func:`~arch.univariate.arch_model` with ``vol="FIAPARCH"``. Analytic forecasts are
  only available for a horizon of 1, and longer horizons require ``method="simulation"``
  or ``method="bootstrap"``. The ``backcast`` of ``fit`` is a variance, as for the other
  volatility processes, and the model with an estimated ``delta`` and the one with the
  same ``delta`` fixed have the same log-likelihood. Contributed by gjunjie
  (:issue:`833`, :issue:`926`).
- Added :class:`~arch.univariate.NGARCH`, the nonlinear asymmetric GARCH volatility
  process of Engle and Ng (1993), which is called NAGARCH in the R package rugarch.
  ``o`` is the number of innovations that have a shift. It can be used in
  :func:`~arch.univariate.arch_model` with ``vol="ngarch"``, which requires ``o`` to be
  at least 1, since a model without a shift is a GARCH. Analytic forecasts are exact at
  all horizons, and simulation and bootstrap forecasts are available. ``fit`` issues a
  ``ValueWarning`` when the estimated persistence is 1 or more, which the estimation
  constraints do not exclude (:issue:`636`, :issue:`966`).
- Added :class:`~arch.univariate.MAMean`, a moving average mean model of order q with an
  optional constant that can be used with any volatility process and distribution.
  Analytic, simulation and bootstrap forecasts include the moving average terms for the
  first q steps. It is a class only: ``arch_model`` does not support ``mean="MA"``.
  Contributed by premdev1234 (:issue:`147`, :issue:`778`, :issue:`903`).
- Added :meth:`~arch.univariate.base.ARCHModel.append` to the mean models, which adds
  new observations to a model in-place. Parameters estimated using earlier data can then
  be used to produce forecasts, or results using
  :meth:`~arch.univariate.base.ARCHModel.fix`, without re-estimating the model. The new
  data must have the same type as the data used to construct the model, and models that
  include exogenous regressors require ``x`` for the new observations (:issue:`674`).
- Added :class:`~arch.covariance.var.PreWhitenedRecolored`, which implements the VAR-HAC
  (den Haan and Levin) and pre-whitened recolored (Andrews and Monahan) long-run
  covariance estimators, and the :class:`~arch.covariance.kernel.ZeroLag` kernel that it
  uses for VAR-HAC, which is selected with ``kernel=None``. The order, residuals and
  residual covariance of the VAR are available as ``order``, ``resid`` and
  ``resid_cov``. Contributed by WatchTree-19 (:issue:`874`, :issue:`894`).
- Added ``bandwidth_method`` to the kernel covariance estimators in
  :mod:`arch.covariance.kernel`, to :class:`~arch.covariance.var.PreWhitenedRecolored`,
  to the ``fit`` methods of :class:`~arch.unitroot.cointegration.DynamicOLS`,
  :class:`~arch.unitroot.cointegration.FullyModifiedOLS` and
  :class:`~arch.unitroot.cointegration.CanonicalCointegratingReg`, and to
  :func:`~arch.unitroot.cointegration.phillips_ouliaris`. The default, ``"newey-west"``,
  is the nonparametric method of Newey and West (1994). ``"andrews"`` is the AR(1)
  plug-in method of Andrews (1991), whose bandwidths equal those of ``bwAndrews`` in the
  R package sandwich (:issue:`887`, :issue:`964`, :issue:`985`).
- Added the residual diagnostics :func:`~arch.univariate.excess_kurtosis`,
  :func:`~arch.univariate.hill_estimator` and :func:`~arch.univariate.var_ratio`, which
  use standardized residuals. The results of a model also have
  :attr:`~arch.univariate.base.ARCHModelResult.excess_kurtosis`,
  :meth:`~arch.univariate.base.ARCHModelResult.hill_estimator` and
  :meth:`~arch.univariate.base.ARCHModelResult.var_ratio`, which use the standardized
  residuals and the estimated distribution of the model. Contributed by albystack
  (:issue:`845`, :issue:`850`).
- Added the VaR backtests :func:`~arch.univariate.var_exceptions`, which finds the
  observations where the loss exceeds the VaR, :func:`~arch.univariate.kupiec_pof`, the
  proportion of failures test of Kupiec (1995),
  :func:`~arch.univariate.christoffersen_independence` and
  :func:`~arch.univariate.christoffersen_conditional_coverage`, the independence and
  conditional coverage tests of Christoffersen (1998), and
  :func:`~arch.univariate.traffic_light`, the zone of the Basel traffic light, which is
  returned as a :class:`~arch.univariate.TrafficLightResult`. ``p`` is always the
  probability of an exception, such as 0.01 for a 99% VaR, and must be in (0, 0.5].
  The unconditional and conditional coverage statistics equal those of ``VaRTest`` in
  the R package rugarch (:issue:`904`, :issue:`965`).
- Added :class:`~arch.bootstrap.LocalBlockBootstrap`, the local block bootstrap of
  Paparoditis and Politis (2002), for series whose properties change slowly over time.
  Each block of the data is replaced by a block that starts at most ``locality``
  observations from it, so that a bootstrap sample only mixes nearby blocks
  (:issue:`617`, :issue:`967`).
- Added ``method="maic"`` to the automatic lag selection of :class:`~arch.unitroot.ADF`,
  :class:`~arch.unitroot.DFGLS` and :class:`~arch.unitroot.ZivotAndrews`. It selects the
  lag that minimizes the modified AIC of Ng and Perron (2001). Contributed by
  ZacKienzle2 (:issue:`889`).
- Added the keyword argument ``low_memory`` to
  :func:`~arch.unitroot.cointegration.engle_granger`, which is passed to the
  :class:`~arch.unitroot.ADF` test of the residuals. The default, ``None``, selects the
  lag selection algorithm automatically. Contributed by ZacKienzle2 (:issue:`876`).
- Kernel names are now looked up in one place,
  ``arch.covariance.kernel.get_kernel_estimator``, using the list
  ``arch.covariance.kernel.KERNELS``. All estimators that take a ``kernel`` accept the
  same names, in any case and with hyphens or underscores ignored, and raise the same
  error, which lists the available kernels, for an unknown name. As a result, the
  ``fit`` methods of :class:`~arch.unitroot.cointegration.FullyModifiedOLS` and
  :class:`~arch.unitroot.cointegration.CanonicalCointegratingReg` accept names such as
  ``"quadratic-spectral"``, which raised ``KeyError`` in previous versions. Contributed
  by WatchTree-19 (:issue:`873`).
- The string options of the public API are not case sensitive, and the lower case
  spelling is stored. For example ``forecast(method="Analytic", align="Target")``,
  ``plot(annualize="d")``, ``ADF(y, trend="C", method="AIC")``,
  ``engle_granger(y, x, trend="CT")``, ``add_trend(x, trend="CT")`` and
  ``IIDBootstrap.conf_int(func, method="BCa", tail="Upper")`` now work, where they
  raised an error in previous versions. The ``method`` of :class:`~arch.bootstrap.MCS`,
  the ``cov_type`` of ``fit`` and the ``form`` of ``ARCHInMean`` are stored in lower
  case. An option that is not accepted raises a ``ValueError`` that lists the accepted
  values (a ``TypeError`` for a value that is not a string). See "Bug fixes" for the
  options that were silently accepted (:issue:`947`).

- Lists and other ``array_like`` objects are accepted as the data of the covariance
  estimators, :class:`~arch.covariance.var.PreWhitenedRecolored`, ``cov_nw``,
  :class:`~arch.bootstrap.SPA`, :class:`~arch.bootstrap.StepM`,
  :class:`~arch.bootstrap.MCS` and the methods of the volatility processes, as the
  models and the unit root tests already did. Data that cannot be converted to
  ``float64``, such as strings, raise a ``TypeError`` that names the argument
  (:issue:`948`).

- Added the keyword argument ``asym_weight`` to the ``forecast`` method of the
  volatility processes. It is the value of :math:`E[z^2 1(z<0)]` of the distribution
  that the analytic forecasts of processes with an asymmetric term use, and the default
  is 0.5 (:issue:`933`, :issue:`939`).
- Integer positions can be negative, and then count from the end as in Python indexing.
  This applies to ``first_obs`` and ``last_obs`` of ``fit`` and ``fix``, to ``start`` of
  ``forecast`` and ``hedgehog_plot``, to ``start`` of the ``forecast`` method of the
  volatility processes, and to the integer arguments of ``cutoff_to_index`` and
  ``find_index`` in ``arch.utility.array``. ``first_obs`` and ``last_obs`` are slice
  bounds, so ``last_obs=-1`` drops the last observation and ``first_obs=-100`` starts
  100 observations from the end. ``start`` is the index of an observation, so
  ``start=-1`` is the last observation. A position outside ``[-nobs, nobs]`` raises a
  ``ValueError``, and dates are unchanged (:issue:`956`).
- ``"horizon"`` is an official alias of ``"target"`` for the ``align`` argument of
  ``forecast`` and of ``ARCHModelForecast``. It is documented, listed in the error for
  an invalid ``align``, and now accepted by the ``forecast`` method of the models, which
  rejected it, as well as by the results (:issue:`956`).

Changes that alter results
~~~~~~~~~~~~~~~~~~~~~~~~~~
These changes fix bugs that returned incorrect results, or make an option that had no
effect work as documented. Each entry says who is affected and, where there is one, how
to restore the previous results.

- Fixed :class:`~arch.bootstrap.SPA` and :class:`~arch.bootstrap.StepM` so that
  ``studentize=True`` (the default) studentizes the loss differentials. In previous
  versions the option had no effect on the results. The loss differentials are now
  studentized in the original data and inside each bootstrap replication, using the
  standard error from a kernel long-run variance estimator that matches the bootstrap,
  or from a nested bootstrap if ``nested=True``. Everyone who uses the default arguments
  is affected: the p-values, the critical values and the superior models can change. Use
  ``studentize=False`` for the statistics that were always used in previous versions.
  Studentizing in each replication makes the default about 3 times slower (measured with
  2000 observations, 100 models and 1000 replications). Started by WatchTree-19
  (:issue:`871`) and completed in :issue:`882`.
- The critical values of :class:`~arch.bootstrap.SPA` and :class:`~arch.bootstrap.StepM`
  apply to the studentized mean loss differentials, so code that compares
  ``critical_values`` with mean loss differentials or that uses fixed thresholds must
  change. In one battery of simulated losses the 5% consistent critical value changed
  from 0.1375 to 2.581 (stationary bootstrap), from 0.1453 to 2.595 (circular) and from
  0.1449 to 2.425 (moving block). With weak evidence (300 observations, 15 models, 300
  replications) the lower, consistent and upper p-values of the stationary bootstrap
  changed from 0.0067, 0.0200 and 0.0200 to 0.0033, 0.0067 and 0.0133, and those of the
  moving block bootstrap from 0.0133, 0.0300 and 0.0367 to 0.0100, 0.0133 and 0.0167, so
  they can move in either direction. With a strongly superior model the p-values are 0
  before and after, and only the critical values change (:issue:`871`, :issue:`882`).
- ``nested=True`` in :class:`~arch.bootstrap.SPA` and :class:`~arch.bootstrap.StepM` now
  computes the variances used to studentize in every bootstrap replication using a
  nested bootstrap, and not only in the original data, and never uses the kernel
  estimator. The run time grows with the square of ``reps``: with 500 observations, 10
  models and 200 replications it increased from 0.04 seconds to about 3 seconds.
  ``nested=True`` requires ``studentize=True`` and raises a ``ValueError`` otherwise, so
  there is no way to restore the previous statistics with ``nested=True``
  (:issue:`882`).
- When ``nested=False``, the long-run variances in :class:`~arch.bootstrap.SPA` and
  :class:`~arch.bootstrap.StepM`, which are used to select the models that are
  re-centered when computing the consistent p-value, now use the kernel that matches the
  bootstrap. Previously they always used the stationary bootstrap kernel, so the
  consistent p-value can also change with ``studentize=False`` when using the circular
  or moving block bootstraps. Results of the stationary bootstrap do not change. In the
  examples that were checked the effect on the critical values was small: the 5%
  consistent critical value of the circular bootstrap changed from 0.1453 to 0.1391
  (-4%), and the 10% value of the moving block bootstrap from 0.1235 to 0.1138 (-8%)
  (:issue:`882`).
- Fixed the simulation and bootstrap forecasts of
  :class:`~arch.univariate.RiskMetrics2006`. The simulated paths started from the
  variance at the forecast origin instead of the one-step-ahead variance, and so the
  forecast of the first step differed from the analytic forecast and the error carried
  into longer horizons. For a zero mean model of the last 1,500 daily S&P 500 returns,
  the simulated variance of the first step at the last origin changes from 3.048 to
  2.774 (-9%), which is the analytic forecast, and the means of the simulated variances
  of the later steps are lower by a similar amount. For a constant mean model of NASDAQ
  returns with Student's t
  errors the variance changes from 3.383 to 5.462 (+61%) at one origin when the
  volatility had just increased. Analytic forecasts, estimation and ``fix`` are not
  changed by this fix. Contributed by WatchTree-19 (:issue:`868`).
- Fixed the multi-step analytic variance forecasts of
  :class:`~arch.univariate.RiskMetrics2006`, which repeated the one-step forecast at
  every horizon. They are now the expected variance path implied by the process, which
  is linear in its EWMA components. Forecasts of the first step do not change, and the
  simulation forecasts are consistent with the analytic ones. For the model above the
  analytic forecast at the last origin, 2.774 at every horizon, becomes 2.774, 2.705,
  2.642 and 2.536 for horizons 1 to 3 and 5 and 2.343 for horizon 10 (-16%). The change
  can have either sign, depending on whether the volatility is above or below its
  long-run level at the origin. There is no option to restore the old forecasts.
  Contributed by raashish1601 (:issue:`885`, :issue:`934`).
- Fixed the multi-step analytic variance forecasts of :class:`~arch.univariate.GARCH`
  models with an asymmetric term (``o > 0``, such as GJR-GARCH),
  :class:`~arch.univariate.MAMean` models and :class:`~arch.univariate.MIDASHyperbolic`
  with ``asym=True``. In previous versions the forecast assumed that half of the
  variance of the standardized residual comes from negative shocks,
  :math:`E[z^2 1(z<0)] = 0.5`, which only holds for symmetric distributions. The
  forecasts now use the value of the distribution, for example of
  :class:`~arch.univariate.SkewStudent`. Forecasts with a symmetric distribution are
  unchanged, and so are simulation and bootstrap forecasts. With a skewed distribution
  the forecasts for horizons beyond 1 change and the change accumulates with the
  horizon: for a GJR-GARCH(1,1,1) model of the last 1,500 daily S&P 500 returns with a
  skew t distribution that has :math:`\eta=7.6` and :math:`\lambda=-0.16` the variance
  forecasts for horizons 10 and 20 at the last origin change from 2.085 and 1.740 to
  2.450 and 2.383. The stationarity constraint of the volatility process and the initial
  value used by ``simulate`` still use the value 0.5 (see :issue:`867`). Contributed by
  shaneraphel (:issue:`870`, :issue:`933`).
- Fixed the acceleration constant of BCa confidence intervals computed by
  :meth:`~arch.bootstrap.IIDBootstrap.conf_int` when the function returns more than one
  statistic. The jackknife estimates of each statistic were centered at the mean of the
  estimates of all of the statistics, and not at their own mean, which changed the
  intervals when the statistics are at different levels. Intervals of a function that
  returns one statistic are not changed. For example, the 90% interval of the mean, when
  an IID bootstrap computes the mean, standard deviation and skewness, changed from
  [-0.1623, 0.0261] to [-0.1625, 0.0253], which is the interval of the mean alone, and
  the lower endpoint for the skewness from -0.0060 to -0.0050. Typical changes of the
  endpoints are 0.2% to 3%, and the largest relative change was 17%, for an endpoint
  near 0. Reported by lucaluo925 and contributed by WatchTree-19 (:issue:`866`,
  :issue:`869`).
- Fixed the residuals and conditional volatility of :class:`~arch.univariate.ARCHInMean`
  results. In previous versions ``resid``, ``conditional_volatility``, ``std_resid`` and
  ``rsquared``, and the quantities derived from them such as the output of ``summary``
  and ``arch_lm_test``, were computed as if the in-mean parameter ``kappa`` was 0, so
  they did not match the log-likelihood. They now use the same recursion as the
  log-likelihood, for all values of ``form`` and for both ``fit`` and ``fix``. The
  estimated parameters, log-likelihood and standard errors are unchanged. The values
  change whenever ``kappa`` is not 0. For example, for a GARCH(1,1) model with one AR
  lag fit to the daily S&P 500 returns in ``arch.data.sp500``, the conditional
  volatility changes by at most 3.7% (``form="log"``), 5.1% (``"vol"``) and 6.1%
  (``"var"``), the largest change in a residual is 0.15, 0.53 and 1.1, and R-squared
  changes from 0.0021 to 0.0021, from 0.0039 to 0.0012 and from 0.0047 to -0.0006.
  R-squared can now be negative for these models (:issue:`909`).
- Fixed :class:`~arch.univariate.ARCHInMean` models that use a
  :class:`~arch.univariate.GARCH` or :class:`~arch.univariate.FIGARCH` volatility
  process with ``power != 2`` (for example ``TARCH`` and ``AVGARCH``). The volatility
  updaters used in estimation returned the recursion value :math:`\sigma^{power}`
  instead of the variance :math:`\sigma^2`, so the in-mean term and the log-likelihood
  used the wrong conditional variance. The log-likelihood, estimates, standard errors
  and ``summary`` change for these models; models with ``power=2`` are unchanged. For
  example, for a GARCH(1,1,1) model with ``power=1`` and one AR lag fit to the second
  half of the daily S&P 500 returns in ``arch.data.sp500``, the log-likelihood changes
  from -3154.8 to -3111.1 and the in-mean coefficient ``kappa`` from 0.217 to 0.059
  (``form="var"``). For a GARCH(1,0,1) model with ``power=1.5`` the log-likelihood
  changes from -3206.3 to -3190.5, and for a FIGARCH(1,d,1) model with ``power=1`` from
  -3284.6 to -3189.9 (:issue:`927`).
- Fixed simulation and bootstrap variance forecasts of :class:`~arch.univariate.APARCH`
  models with ``p >= 2`` and ``o >= 1``. In previous versions the asymmetric term
  ``|e| - gamma * e`` overwrote the stored absolute shock, so from the second forecast
  horizon on the lagged shocks were wrong. Analytic, one-step and ``p = 1`` forecasts
  are unchanged. The size of the change depends on the parameters, the data and the
  horizon: the simulated variance forecast of an APARCH(2,1,1) model changed by between
  7% and 34% in the cases that were checked (12% at ``horizon=2`` in a typical case,
  from 0.271 to 0.239) and by about 1% for a model of S&P 500 returns with moderate
  parameters (:issue:`911`).
- Fixed simulation forecasts of :class:`~arch.univariate.GARCH` models with
  ``power != 2`` (for example ``TARCH`` and ``AVGARCH`` models) that start in the first
  ``max(p, o, q)`` observations. In previous versions the pre-sample values were raised
  to the power ``power / 2`` a second time, so the forecast made at ``start=0`` was
  wrong for any model with more than one lag. Forecasts that start later in the sample,
  and the analytic and bootstrap forecasts, are unchanged. For example, the one-step
  simulated variance of a GARCH(2,0,0) model with ``power=1`` at the first observation
  changes from 0.4184 to 0.4059 (3.1%), and that of a GARCH(2,1,2) model with
  ``power=1`` changes by 3.6% (:issue:`913`).
- Fixed ``conf_int`` with ``sampling="semi-parametric"`` or ``sampling="parametric"`` in
  the bootstrap classes in :mod:`arch.bootstrap`. In previous versions the ``params``
  (and ``state``) keywords used to simulate the data were added to the data of the
  bootstrap, so ``method="studentized"`` raised an error when the studentization used a
  nested bootstrap. When ``extra_kwargs`` was also given, the nested bootstrap silently
  used the non-parametric statistic. The nested bootstrap now simulates the data in the
  same way as the outer bootstrap, so studentized intervals from the nested bootstrap
  with these samplers change from previous versions (:issue:`916`).
- Fixed :class:`~arch.unitroot.cointegration.CanonicalCointegratingReg` so that
  ``df_adjust=True`` scales the entire estimate of the conditional long-run variance, as
  :class:`~arch.unitroot.cointegration.FullyModifiedOLS` does. Previously only the first
  term was scaled, which overstated the parameter covariance and ``long_run_variance``
  when the regressors are endogenous. Results using the default, ``df_adjust=False``,
  are not changed. In regressions with 390 to 400 observations and 2 or 3 regressors the
  covariance and long-run variance fall by 0.016% to 0.15%, the standard errors and
  t-values by 0.008% to 0.07%, and the p-values by up to 1.3%. In a small sample (100
  observations, an endogenous regressor and a bandwidth of 4) the standard errors with
  ``df_adjust=True`` were 1.9% larger than with ``df_adjust=False`` and are now 1.0%
  larger, and the long-run variance was 3.8% larger and is now 2.1% larger. Contributed
  by WatchTree-19 (:issue:`872`).
- Fixed :class:`~arch.unitroot.DFGLS` when the data are integers. The quasi-differenced
  data were truncated to integers, which produced a statistic and p-value that differ
  from those of the same data stored as floats. Results for data that are floats are not
  changed. For example, the statistic of one integer series changed from -0.3005 to
  -0.3378, and its p-value from 0.581 to 0.567 (and, with ``lags=2``, the statistic from
  -0.2618 to -0.2970). Convert the data to floats to obtain the previous statistic.
  Contributed by raashish1601 (:issue:`883`).
- Fixed :func:`~arch.unitroot.auto_bandwidth` so that the autocovariances are not
  truncated to integers. In previous versions any series with non-integer values could
  return an incorrect bandwidth or raise ``ZeroDivisionError``, which happened when all
  of the autocovariances were less than 1 in absolute value. For example, the bandwidths
  for the Bartlett, Parzen and quadratic spectral kernels of daily S&P 500 percent
  returns change from 9.655, 19.65 and 7.223 to 9.816, 19.94 and 7.256 (+1.7%, +1.5% and
  +0.5%), and the Bartlett and quadratic spectral bandwidths of the first difference of
  the AAA bond yield change from 9.17 and 1.956 to 9.76 and 3.142 (+6.4% and +61%). Only
  :func:`~arch.unitroot.auto_bandwidth` is affected: the kernel classes,
  :class:`~arch.unitroot.PhillipsPerron` and :class:`~arch.unitroot.KPSS` do not use it.
  Contributed by ZacKienzle2 (:issue:`886`).
- Fixed the automatic bandwidth of the kernel covariance estimators in
  :mod:`arch.covariance.kernel`, so that the bandwidths and the estimates equal those of
  the R package sandwich. Every estimate with an automatic bandwidth changes, including
  those of :class:`~arch.covariance.var.PreWhitenedRecolored`,
  :class:`~arch.unitroot.cointegration.DynamicOLS`,
  :class:`~arch.unitroot.cointegration.FullyModifiedOLS`,
  :class:`~arch.unitroot.cointegration.CanonicalCointegratingReg` and
  :func:`~arch.unitroot.cointegration.phillips_ouliaris` when ``bandwidth`` is not
  given. There are three changes:

  * The number of autocovariances in the pilot estimate of the optimal bandwidth,
    ``opt_bandwidth``, is the integer part of :math:`4(T/100)^{r}`, as in Newey and West
    (1994) and :func:`~arch.unitroot.auto_bandwidth`. Previously it was rounded up, so
    that one more autocovariance was used whenever :math:`4(T/100)^{r}` is not an
    integer. ``opt_bandwidth`` now equals ``bwNeweyWest`` of sandwich.
  * The kernels that are 0 beyond a finite lag, which are all except the quadratic
    spectral kernel, weight lag :math:`h` by :math:`k(h/(H+1))` for a bandwidth
    :math:`H`, while the optimal bandwidth :math:`S` of Andrews (1991) and Newey and
    West (1994) is that of :math:`k(h/S)`. :math:`S` was used as :math:`H`, which gave
    the weights of :math:`S+1`. The estimated ``bandwidth`` of these kernels is now
    :math:`\max(S-1, 0)`, so that the weights are those of :math:`S`, as in
    ``kernHAC`` of sandwich (and ``NeweyWest`` for the Bartlett kernel with
    ``force_int=True``). ``opt_bandwidth`` is still :math:`S`, and so
    ``Bartlett(x, bandwidth=est.opt_bandwidth)`` is not the same as ``Bartlett(x)``.
  * A bandwidth that is not an integer, estimated or given, uses every lag with a
    positive weight. The lag :math:`\lfloor H \rfloor + 1` was not used. An integer
    ``bandwidth`` gives the same estimates as before.

  For example, the Bartlett, Parzen and quadratic spectral bandwidths of the daily S&P
  500 percent returns in ``arch.data.sp500`` change from 22.88, 31.99 and 13.25 to
  30.96, 34.50 and 13.61, and their ``opt_bandwidth`` to 31.96, 35.50 and 13.61. The
  constant of the Tukey-Parzen kernel is also corrected from 1.8576 to 1.8587, which
  changes its automatic bandwidth slightly. Pass ``bandwidth`` to use a specific value
  (:issue:`964`, :issue:`983`).
- Fixed the critical values and p-values of the ADF-Z statistic without a trend
  (``regression="n"``), which :class:`~arch.unitroot.PhillipsPerron` uses with
  ``test_type="rho"`` and ``trend="n"``, and which ``mackinnoncrit`` and ``mackinnonp``
  return with ``dist_type="adf-z"``. The values are from a new simulation that starts
  the random walk at 0. The 1%, 5% and 10% critical values with 100 observations change
  from -10.78, -6.13 and -4.27 to -13.08, -7.78 and -5.56, and the asymptotic ones from
  -13.30, -7.83 and -5.57 to -13.69, -8.04 and -5.71. In small samples the previous
  critical values were wrong: with 10 observations they were 20.32, 13.84 and 10.54,
  and are now -8.95, -5.98 and -4.41. For example the p-value of a statistic of -8
  changes from 0.0477 to 0.0504. The tables with a constant or a trend are also from the
  new simulation. Their critical values change by less than 0.005 with 25 or more
  observations and their p-values below 0.15 by at most 0.0001. Contributed by mkzung
  (:issue:`971`, :issue:`972`, :issue:`973`, :issue:`980`).
- The p-value of the ADF-Z statistic, which :class:`~arch.unitroot.PhillipsPerron` uses
  with ``test_type="rho"`` and ``mackinnonp`` returns with ``dist_type="adf-z"``, is now
  a smooth and increasing function of the statistic. It is approximated by one
  polynomial below a cut-off and another above it. These were estimated separately, so
  the p-value jumped down at the cut-off, by 0.033 with ``"n"``, 0.014 with ``"c"``,
  0.010 with ``"ct"`` and 0.008 with ``"ctt"``. The two are now estimated jointly, so
  that they have the same value and slope at the cut-off. The approximation of the
  middle of the distribution is also more accurate: the largest difference from the
  simulated distribution is now 0.012 with ``"n"`` and at most 0.0015 otherwise.
  Compared with 8.0, with a constant or a trend, p-values below 0.15 change by at most
  0.0001, and the largest change is 0.013, at p-values between 0.7 and 0.8. The
  critical values are unchanged (:issue:`989`).
- Integer, unsigned integer and Boolean data are now converted to ``float64`` when they
  are passed to an estimator, so that no calculation is done in integer arithmetic.
  Previously a calculation that used the products or differences of integer data could
  overflow, wrap around or lose precision. For example, the kernel covariance estimators
  and ``cov_nw`` computed the sums of squares of ``int64`` data with values near 2**32
  in ``int64`` when ``center=False`` or ``demean=False``; :class:`~arch.unitroot.ADF`,
  :class:`~arch.unitroot.VarianceRatio`,
  :class:`~arch.unitroot.cointegration.DynamicOLS` and
  :class:`~arch.unitroot.cointegration.FullyModifiedOLS` took the differences of
  ``uint8`` data, which wrap around below 0; and :class:`~arch.univariate.FixedVariance`
  took the square root of ``uint8`` variances in ``float16``. All of these now give the
  same result as the same data stored as ``float64``, which is passed through without a
  copy. The data of the bootstraps are not converted, since they are passed to the
  function of the user as given (:issue:`948`).

  The same rules for the data type apply to all of the estimators, the tests, the
  models, the volatility processes and the distributions. Integer, unsigned integer,
  Boolean, ``float32`` and ``longdouble`` data are converted to ``float64``, and every
  calculation is done in ``float64``, so the result for ``float32`` data is the result
  for the same values stored as ``float64``. ``float32`` is promoted because a
  calculation in ``float32`` is not accurate enough: when all of the arrays of the unit
  root tests are ``float32``, the Phillips-Perron statistic of a series with a large
  level differs from its ``float64`` value by up to 0.04, and the lag search of
  :class:`~arch.unitroot.ADF` fails with a singular matrix for a series with a large
  level or a trend and thousands of observations. ``float16`` data are never accepted:
  they raise a ``TypeError`` that names the argument and the accepted data types, and
  can be converted using ``astype(np.float32)`` or ``astype(np.float64)``. Complex data
  also raise a ``TypeError``, except for the functions that estimate a Hermitian
  covariance (see the entry about complex data). The fixes of the covariance estimators
  and of the ``axis`` of ``cov_nw``, and the first support of ``float32`` and complex
  data in the covariance estimators, were contributed by antonsoo (:issue:`942`,
  :issue:`943`, :issue:`957`).
- The kernel covariance estimators in :mod:`arch.covariance.kernel` and ``cov_nw``
  accept complex data, and estimate the Hermitian long-run covariance. The products use
  the conjugate transpose, so that the lag-j autocovariance is the sum of ``x[t]`` times
  the conjugate of ``x[t - j]``, the automatic bandwidth uses the real part of the
  autocovariances of the complex series, and the estimates are Hermitian ``complex128``
  matrices with a real diagonal. For ``z = a + ib`` the long-run covariance is the
  covariance of ``a`` plus the covariance of ``b`` plus ``i`` times the cross-covariance
  of ``b`` and ``a`` less that of ``a`` and ``b``, computed from the real data of ``a``
  and ``b`` with the same kernel and bandwidth. The pseudo-covariance, which has no
  conjugate, is not estimated. ``cov_nw`` returns a real float for a 1-d complex series.
  In 8.0 the kernel estimators failed for complex data, and ``cov_nw`` had no conjugate,
  so that its result was not Hermitian. ``add_trend`` also accepts complex data, and
  adds real trend columns to them. The ``apply``, ``cov`` and ``var`` of the bootstraps
  accept a statistic that returns complex values: ``cov`` is the Hermitian covariance
  and ``var`` is real, where the imaginary part used to be discarded with a
  ``ComplexWarning``. ``conf_int`` raises a ``TypeError`` for a complex statistic, which
  has no interval. :class:`~arch.covariance.var.PreWhitenedRecolored`, the tests and the
  models do not accept complex data, since there is no single model of complex data for
  the VAR that prewhitens the data. Thanks to antonsoo for the support of complex data
  in the covariance estimators that this builds on (:issue:`942`, :issue:`957`).

- ``fit`` ignores ``starting_values`` that violate the bounds or constraints of the
  model, with the ``StartingValueWarning`` that was always issued. In previous versions
  the optimization was still started from the invalid values. Such fits start from the
  values constructed by the model and can converge to different estimates. Values with
  the wrong length or with NaN or inf now raise (see "Backward-incompatible changes").
  The ``first_obs``, ``last_obs`` and ``start`` of ``fit``, ``fix`` and ``forecast`` now
  accept ``datetime.date`` and ``pandas.Period`` values and a ``pandas.PeriodIndex``. A
  ``date`` or ``Period`` was silently ignored in previous versions, so the whole sample
  was used and ``forecast`` only forecast the last observation, and now the requested
  sample is used (:issue:`925`).
- Fixed :class:`~arch.unitroot.cointegration.DynamicOLS` with ``method`` in upper case.
  The method was validated in lower case but compared in its original case, so that
  ``"AIC"`` and ``"HQIC"`` selected the leads and lags using BIC, and now select them
  using the criterion that was requested (:issue:`947`).

- Fixed ``APARCH.starting_values`` with ``common_asym=True`` and ``o > 1``, which ranked
  the candidate starting values using the likelihood at the wrong parameters (the betas
  were taken from the positions of the gammas). The starting values, and so the
  estimates, of these models can change (:issue:`949`).

- :class:`~arch.bootstrap.MCS` now includes a model in ``included`` if its p-value is
  greater than or equal to ``size`` (previously strictly greater), and lists it in
  ``excluded`` only if the p-value is less than ``size`` (previously less than or
  equal). A model is in the model confidence set of size alpha if its MCS p-value is at
  least alpha. Bootstrap p-values are multiples of ``1 / reps``, so a p-value equal to
  ``size`` occurs in practice and the model was previously excluded (:issue:`944`).

- The simulation and bootstrap forecasts of :class:`~arch.univariate.FIGARCH` add the
  terms of the ARCH(:math:`\infty`) representation in a different order, so that, given
  the same random numbers, the simulated variances, shocks and forecasts can differ from
  those of earlier versions in the last bits. The largest relative differences measured
  are about 1e-15. Analytic forecasts, estimates and the log-likelihood are unchanged
  (:issue:`940`).
- The standard errors, t-statistics, p-values and ``param_cov`` of ``ARX`` models with a
  ``DataFrame`` of exogenous regressors differ from those of 8.0 in the fifth to seventh
  significant digit (up to 4e-5, relative), because the regressors are now passed to the
  compiled code as a C-contiguous array. The parameters and the log-likelihood are
  unchanged (:issue:`674`).

Backward-incompatible changes
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
- The ``bootstrap`` attribute of :class:`~arch.bootstrap.SPA`,
  :class:`~arch.bootstrap.StepM`, ``RealityCheck`` and :class:`~arch.bootstrap.MCS` is
  now a read-only property. Assigning a bootstrap to an existing instance raises
  ``AttributeError``, since quantities that depend on the bootstrap are computed when
  the instance is created. Create a new instance to use a different bootstrap
  (:issue:`882`).
- ``nested=True`` with ``studentize=False`` in :class:`~arch.bootstrap.SPA` and
  :class:`~arch.bootstrap.StepM` raises a ``ValueError``. The combination was accepted
  in previous versions (:issue:`882`).
- ``block_size`` of :class:`~arch.bootstrap.CircularBlockBootstrap`,
  :class:`~arch.bootstrap.MovingBlockBootstrap` and
  :class:`~arch.bootstrap.StationaryBootstrap` is now a read-only property, and setting
  it raises an ``AttributeError``. In previous versions the attribute could be set, but
  the stationary bootstrap ignored the new value when sampling and ``clone``, which is
  used for the nested bootstrap of studentized confidence intervals, used the value
  passed to the constructor. Create a new bootstrap to use a different block size
  (:issue:`944`).

- ``std_err_func`` in ``conf_int`` no longer receives the ``params`` and ``state``
  keywords that are used to simulate data when ``sampling`` is ``"semi-parametric"`` or
  ``"parametric"``. It is called as ``std_err_func(params, *args, **kwargs)``, where
  ``params`` is the estimate and ``kwargs`` contains only the data and ``extra_kwargs``.
  Previously a ``std_err_func`` with a first argument named ``params`` raised a
  ``TypeError`` for these samplers (:issue:`916`).
- The ``type`` keyword argument of
  :meth:`~arch.univariate.base.ARCHModelFixedResult.hedgehog_plot` has been removed. See
  "Deprecations and removals" (:issue:`945`).

- ``fit`` raises a ``ValueError`` for a ``cov_type`` other than ``"robust"`` or
  ``"classic"`` (in any case). Previously any other value, such as ``"White"`` or
  ``"mle"``, was silently treated as ``"classic"`` unless the model has a closed-form
  estimator, and the results reported the unknown value (:issue:`925`).
- ``first_obs``, ``last_obs`` and ``start`` of ``fit``, ``fix`` and ``forecast`` must be
  an integer position in ``[-nobs, nobs]``, a date inside the index, or ``None``. A
  float such as ``first_obs=10.0``, a Boolean or a list raises a ``TypeError`` (they
  were silently ignored, so the whole sample was used), and a position or date outside
  the sample raises a ``ValueError``: ``fit(first_obs=-1000)`` recorded ``-1000`` as
  ``fit_start``, ``fit(last_obs=10**6)`` recorded ``10**6`` as ``fit_stop``, and
  ``forecast(start=10**6)`` failed with "negative dimensions are not allowed". A string
  or date used with data that have no ``DatetimeIndex`` or ``PeriodIndex`` raises a
  ``ValueError``, where it was an ``AssertionError`` (:issue:`925`, :issue:`949`).

- Every public function, constructor and method now checks its arguments when it is
  called or created, before any computation. An error names the argument, says what is
  accepted and shows the value received, for example
  ``reps must be an integer >= 1; got 0 (int)``. A value of the wrong type raises a
  ``TypeError`` and a value that is not allowed (outside its range, not one of the
  options, of the wrong shape or length, or NaN or inf where finite values are needed)
  raises a ``ValueError``. Integer arguments must be Python or NumPy integers: floats,
  including ``5.0``, and Booleans are rejected. Flags must be ``bool``, ``np.bool_`` or
  the integers ``0`` and ``1``: ``"no"``, ``None`` and ``2`` were accepted before and
  used for their truth value. NaN and inf in data raise, except where they are handled
  by design (the data of the bootstraps, which are passed to the function of the user,
  the diagnostics that drop NaN, and the residuals of a fitted model). Code that relied
  on the earlier behavior needs to change. The entries below list the calls that are
  affected, and the policy is described in the contributing guide (:issue:`949`,
  :issue:`956`).
- Flags accept ``bool``, ``np.bool_`` and the integers ``0`` and ``1`` (Python and NumPy
  integers), which are converted to ``bool``. This applies to every argument that the
  entries on the validation of arguments call a ``bool``. An integer other than ``0``
  and ``1`` raises a ``ValueError``, and a float (including ``1.0``), a string, an
  array and ``None`` raise a ``TypeError``, except that ``None`` is accepted where it is
  the documented default (``low_memory`` and ``rescale``). The ``disp`` of ``fit`` is
  ``"off"``, ``"final"`` or a flag, so that ``disp=0`` is ``"off"`` and ``disp=1`` is
  ``"final"``. The ``exit`` and ``append`` of ``arch.test`` are now checked as flags
  (:issue:`956`).

- The unit root tests (:class:`~arch.unitroot.ADF`, :class:`~arch.unitroot.DFGLS`,
  :class:`~arch.unitroot.PhillipsPerron`, :class:`~arch.unitroot.KPSS`,
  :class:`~arch.unitroot.VarianceRatio` and :class:`~arch.unitroot.ZivotAndrews`) check
  all of their arguments when the test is created, including the length of the series
  against ``lags`` and ``max_lags``. ``lags=2.5`` (truncated to 2), ``lags="2"`` and
  ``lags=True`` raise a ``TypeError``, and a negative ``lags`` or ``max_lags`` a
  ``ValueError`` (``KPSS`` still accepts ``lags=-1``). ``low_memory``, ``debiased``,
  ``robust`` and ``overlap`` must be ``bool`` (``low_memory`` also accepts ``None``).
  NaN or inf in the data raise
  ``ValueError: y must be a 1-d array of finite numbers; got 1 NaN (ndarray)``, where
  ``ADF``, ``DFGLS`` and ``ZivotAndrews`` raised ``LinAlgError``, ``PhillipsPerron``
  statsmodels' ``MissingDataError``, ``KPSS`` a ``ValueError`` about converting NaN, and
  ``VarianceRatio`` returned NaN. The same applies to
  :func:`~arch.unitroot.auto_bandwidth` (:issue:`949`).

- The unit root tests no longer return a statistic that cannot be estimated. A
  regression in ``ADF`` or ``DFGLS`` with as many parameters as observations used to
  return a statistic of 0.0 because the residual degrees of freedom were 0, for example
  ``ADF(y[:14], lags=8).stat``. An ``ADF`` with ``lags`` lags and ``k`` trend terms now
  needs at least ``3 + 2 * lags + k`` observations, and ``DFGLS`` needs
  ``3 + 2 * lags``. A ``max_lags`` that is too large for the series, which raised
  ``LinAlgError`` or an error from statsmodels, now raises
  :class:`~arch.utility.exceptions.InfeasibleTestException` when the test is created.
  The messages of this exception name the test, ``y`` and the number of observations
  (the messages of ``PhillipsPerron``, ``KPSS`` and ``VarianceRatio`` said that an "ADF"
  could not be run) (:issue:`949`).

- :class:`~arch.utility.exceptions.InfeasibleTestException`, which the unit root tests
  raise if the series is too short or the specification cannot be estimated, is now also
  a ``ValueError``. It is still a ``RuntimeError``, so code that catches either keeps
  working (:issue:`949`).

  (:func:`~arch.unitroot.cointegration.engle_granger`,
  :func:`~arch.unitroot.cointegration.phillips_ouliaris`,
  :class:`~arch.unitroot.cointegration.DynamicOLS`,
  :class:`~arch.unitroot.cointegration.FullyModifiedOLS` and
  :class:`~arch.unitroot.cointegration.CanonicalCointegratingReg`) check ``y`` and ``x``

  :class:`~arch.covariance.var.PreWhitenedRecolored` and ``cov_nw`` are checked when the

  ignored (:issue:`949`).

  those of ``simulate`` and ``forecast`` when they are called. The orders ``p``, ``o``
  and ``q``, ``m`` of :class:`~arch.univariate.MIDASHyperbolic` and ``truncation`` of

  rejects ``start`` outside ``[-len(resids), len(resids)]``, ``simulations=0`` and an
  ``asym_weight`` that is not in [0, 1]. ``rng=None`` with ``method="simulation"``
  raises a ``TypeError`` and not an ``AssertionError`` (:issue:`949`).

  ``parameters[0] (nu) must be a finite float in [2.05, 500]; got 1.0 (float)``, where

- The ``starting_values``, ``backcast`` and ``compute_variance`` methods of the
  volatility processes and the ``loglikelihood`` methods of the distributions raised an
  error for integer arrays, and for lists. ``add_trend`` failed on Boolean data. A
  ``Series`` without a name that is passed by the user, for example to
  :func:`~arch.univariate.arch_model`, is no longer renamed to the string ``"None"``
  (:issue:`948`).

- Fixed the bootstraps of a statistic that returns the same array in every call, for
  example one that writes its result with NumPy's ``out=`` argument. The estimate of the
  original sample and the jackknife estimates were overwritten by later calls, which
  shifted the confidence intervals, changed ``cov`` and ``var`` and could make BCa
  raise an error. They are now copied. Contributed by antonsoo (:issue:`954`).
- Fixed ``partial_moment`` of :class:`~arch.univariate.StudentsT` for odd orders when
  ``nu`` is 342 or more, which returned 0. For example the first partial moment at 0
  with ``nu=342`` is -0.39865. The partial moments of :class:`~arch.univariate.Normal`
  and :class:`~arch.univariate.StudentsT` of order 2 or more at ``-inf`` and ``inf``,
  which were NaN, are 0 and the moment of that order. Contributed by mkzung
  (:issue:`969`, :issue:`970`, :issue:`985`).
- Small p-values are no longer rounded to 0. The p-value of
  :class:`~arch.utility.testing.WaldTestStatistic`, which the ARCH LM test and other
  tests return, the p-value of :class:`~arch.unitroot.VarianceRatio` and the
  ``pvalues`` of the results of :class:`~arch.unitroot.cointegration.DynamicOLS`,
  :class:`~arch.unitroot.cointegration.FullyModifiedOLS` and
  :class:`~arch.unitroot.cointegration.CanonicalCointegratingReg` were computed as 1
  minus a CDF, which is 0 for p-values smaller than about 1e-16. For example the
  p-value of a Wald statistic of 100 with 2 degrees of freedom was 0 and is 1.9e-22.
  Contributed by galafis (:issue:`975`, :issue:`977`).
- :attr:`~arch.bootstrap.StepM.superior_models` returns Python integers for the models
  that are found after the first step, which were NumPy integers. Contributed by
  wavebyrd (:issue:`974`).
- Fixed ``add_trend`` for a ``DataFrame`` with a duplicated index, which multiplied the
  rows and mixed the trend values of different observations. The trend columns are now
  added by position. Contributed by jackiectl2 (:issue:`978`).
- Object data, including object ``Series`` and ``DataFrame`` columns, whose elements are
  complex numbers with imaginary parts that are all 0 are converted to ``float64``, as
  for real numbers. They were rejected unless complex data are allowed, and were then
  ``complex128``. Contributed by galafis (:issue:`976`, :issue:`982`).
- The automatic bandwidth of the kernel covariance estimators and of
  :class:`~arch.covariance.var.PreWhitenedRecolored` raises a ``ValueError`` for data in
  which every column is constant, as ``bandwidth_method="andrews"`` does, where it
  raised a ``ZeroDivisionError`` (:issue:`985`).
- ``mackinnonp`` returns 0 for a statistic of ``-inf`` and 1 for ``inf``, where it
  returned NaN for the ADF-Z tables and for the ADF test without a trend, and no longer
  warns about an overflow for a very large statistic (:issue:`985`).

Performance
~~~~~~~~~~~
- Automatic lag selection in :class:`~arch.unitroot.DFGLS` no longer estimates an
  :class:`~arch.unitroot.ADF` test whose result was discarded, which makes it several
  times faster (:issue:`890`). Contributed by ZacKienzle2.
- :class:`~arch.bootstrap.MCS` no longer copies the resampled losses in each bootstrap
  replication (:issue:`895`). Contributed by ZacKienzle2.
- The long-run variance of the loss differentials that :class:`~arch.bootstrap.SPA` and
  :class:`~arch.bootstrap.StepM` use when ``nested=False`` is computed using an FFT,
  which makes ``studentize=False`` about twice as fast as in previous versions
  (:issue:`882`).
- Evaluating the variance recursions of :class:`~arch.univariate.FIGARCH`,
  :class:`~arch.univariate.HARCH` and :class:`~arch.univariate.MIDASHyperbolic` models
  is about 3, 4 and 1.4 times faster with the compiled recursions, so that estimating a
  FIGARCH model with the default truncation of 1000 is about 2.5 times faster.
  Simulating from :class:`~arch.univariate.HARCH` and
  :class:`~arch.univariate.MIDASHyperbolic` models is 3 to 30 times faster, and the
  multi-step analytic forecasts of :class:`~arch.univariate.ARCH` and
  :class:`~arch.univariate.GARCH` models are computed for all forecast origins at once,
  which makes forecasting every observation of a sample of 5000 observations 10 steps
  ahead about 80 times faster (:issue:`940`).
- The simulation and bootstrap forecasts of :class:`~arch.univariate.FIGARCH` compute
  the contribution of the observed history once for each forecast origin and horizon,
  and not once for each simulated path. Forecasting 100 origins 10 steps ahead using
  1000 paths and a truncation of 1000 is about 20 to 30 times faster (:issue:`940`).

Deprecations and removals
~~~~~~~~~~~~~~~~~~~~~~~~~
- Removed the ``type`` keyword argument of
  :meth:`~arch.univariate.base.ARCHModelFixedResult.hedgehog_plot`, which has been
  deprecated in favor of ``plot_type`` since 4.0. Passing ``type`` now raises a
  ``TypeError`` (:issue:`945`).

- :class:`~arch.unitroot.KPSS` no longer issues a ``DeprecationWarning`` when ``lags``
  is not provided. The data-dependent lag selection has been the default since 4.8. Use
  ``lags=-1`` for the lag length that depends only on the sample size (:issue:`945`).

- Removed the empty module ``arch.__future__``. The import
  ``from arch.__future__ import reindexing`` has been a no-op since 6.2, and now raises
  a ``ModuleNotFoundError`` (:issue:`945`).

- Removed the unused module-level string templates ``deprecation_doc`` from
  ``arch.utility.array`` and ``arch.utility.exceptions`` (:issue:`945`).

Compatibility
~~~~~~~~~~~~~
- Python 3.10 to 3.15 are supported, and wheels are available for Linux (manylinux on
  x86-64 and aarch64, and musllinux on x86-64), Windows (AMD64) and macOS (arm64 and
  x86-64) for each of them. 9.0 is the last release that supports Python 3.10 and NumPy
  1.x. Later releases will raise the other minimum versions accordingly.
- Building from source requires Cython 3.1.0 or later.
- Running the test suite requires pytest 9 or later.
- Improved compatibility with current and upcoming releases of NumPy and pandas: the
  warning of pandas 3.1 for time zone aware indices in date lookups is fixed, and the
  code no longer sets the ``shape`` of arrays (:issue:`842`, :issue:`912`).
- The scalar results of ``Normal.ppf``, ``SkewStudent.cdf`` and ``mackinnonp`` are
  Python ``float`` values and no longer ``numpy.float64``.

Minimum versions
~~~~~~~~~~~~~~~~
- The minimum version of statsmodels is now 0.13.1. Version 0.13.0 has no wheels for
  Python 3.10.
- The minimum versions of Python (3.10), NumPy (1.22.3), SciPy (1.8) and pandas (1.4.0)
  have not changed. Building from source requires Cython 3.1.0, and running the tests
  requires pytest 9.
